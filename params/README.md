# params/ — パラメータレジストリ

769 パラメータの**機械可読な定義**。売買コードはこのレジストリから生成する。

md とコードで定義を二重管理すると必ずずれるので、
[docs/01_parameter_catalog.md](../docs/01_parameter_catalog.md) を人間向けの正典、
このディレクトリをその機械可読な投影として扱う。

---

## 3層構造

```
  docs/01_parameter_catalog.md      … 1. カタログ表（人間が読む正典）
            │                            definition / sign / 買売 / horizon /
            │                            data_sources / evidence_stars を導出
            ▼
  params/_defaults.yaml             … 2. プロジェクト規約（決定事項）
            │                            連結 / 欠損方針 / 正規化母集団 /
            │                            PITラグ / 会計期間の既定
            ▼
  params/_overrides_oap.yaml        … 3. OSAP 突合で機械充填した q11
            │                            tools/crosswalk_oap.py が生成
            ▼
  params/_overrides.yaml            … 4. 人によるレビュー結果【最優先】
            │                            12問に答えた内容。再生成しても失われない
            ▼
  params/A.yaml … Z.yaml            … 生成物
  params/_meta.yaml                      各項目の出所は provenance に記録
```

> **A.yaml 〜 Z.yaml と _meta.yaml は生成物である。直接編集しない。**
> 直すべき対象は、カタログ md か `_defaults.yaml` か `_overrides.yaml` のいずれか。
> `_overrides_oap.yaml` も生成物なので、直すなら `_oap_crosswalk.yaml`（対応表）の方を直す。

## コマンド

```bash
python tools/build_registry.py            # 生成 / 更新
python tools/build_registry.py --check    # 書き込まず、md と yaml の乖離だけ検査（CI用）
python tools/validate_registry.py         # スキーマ検証 + 進捗レポート
python tools/validate_registry.py --report  # カテゴリ別・実証度別の内訳も出す
```

`--check` が落ちたら、カタログを編集したのに再生成していない（レジストリが陳腐化している）。

## `review.status` の意味

| status | 意味 |
|---|---|
| `draft` | カタログ表と規約から自動生成されただけ。**実装してはいけない** |
| `reviewed` | 12問の一部に答えた途中状態 |
| `verified` | **12問すべてに答えた。** `pending` が空で、必須項目が全部埋まっている |

`pending` は手で書かない。`provenance` から自動計算される。
`verified` なのに `pending` が残っていたら validator がエラーで落とす。

## レビューのやり方

1. `params/<CAT>.yaml` で対象パラメータの `review.pending` を見る
2. [docs/02_definition_spec.md §8](../docs/02_definition_spec.md) の12問に答える
3. 答えを `params/_overrides.yaml` に追記する（部分上書きでよい）
4. すべて埋まったら `review: {status: verified}` を付ける
5. `python tools/build_registry.py && python tools/validate_registry.py` を通す

### 12問と対応フィールド

| 問 | フィールド | 規約で決まるか |
|---|---|---|
| q01 | `period_convention` | A〜F・U・V 以外は規約で確定 |
| q02 | `pit_lag_days` | **規約で確定**（データ源から導出） |
| q03 | `consolidation` | **規約で確定** |
| q04 | `accounting_standard_note` | A〜F・U・V 以外は `na` |
| q05 | `zero_denominator_policy` | 除算を含まないものは `na` |
| q06 | `missing_bias` | **常に個別判断**（欠損の偏りは Z03 に直結する） |
| q07 | `normalization` | **規約で確定**（カテゴリ別） |
| q08 | `nonlinear` | ∩/∪ のみ個別判断（x* の決め方） |
| q09 | `correlated_with` | **常に個別判断** |
| q10 | `economic_rationale` | **常に個別判断。書けないものは採用しない** |
| q11 | `evidence_tier` + `references` | **常に個別判断。一次文献にリンクする** |
| q12 | `markets` | K カテゴリのみ導出済み |

加えて、`buy_class` / `sell_class` が `gate` のものは **`gate_policy`（実行可能な閾値）が必須**。
閾値のないゲートは実装できない。

### 根拠が「構造的判断のみ」の10件

validator が警告として出す。**欠陥ではなく、判断の所在を可視化するための印。**

`D02 D04 D07 D22 E08 E12 J02 J13 K45 T13`

これらは実証論文ではなく論理的必然（債務超過の企業を買わない、監査意見が付かない企業を買わない、
出口が確保できないサイズを建てない）に基づく。**閾値の妥当性は Phase 1 で較正する（OQ-23）。**
「ゲートを通した群 vs 通さない群」の成績差を測れば、どのゲートが実際にエッジを守り、
どれが単にユニバースを痩せさせているだけかが分かる。

## レビュー中に見つかった設計上の問題

レジストリを埋める作業自体が検証になっている。現時点で出てきたもの:

- **N02 / N10 の欠損は日本の小型株に集中している。**
  アナリストコンセンサスを前提にした PEAD・リビジョン系は、無カバー62%という
  本プロジェクトの中核ユニバースで丸ごと計算できない。
  会社予想版（GUIDE_CO）と四季報版（K32/K33）の整備が実質的に必須（catalog OQ-22）。
- **B10 の分母（営業利益）が負のときに欠損にしないと、赤字企業が「現金化率が良い」と誤判定される。**
  この手の符号の罠は、12問の q05 を通さないと見つからない。
- **F02（5年株式発行率）は上場5年未満の企業が丸ごと欠損する。**
  結果としてユニバースが暗黙に成熟企業へ偏る。Z03 での監視が必要。
- **ゲートの閾値はすべて初期提案であり、実証的根拠はまだない**（catalog OQ-23）。

### O カテゴリ（ネグレクト）の検証で出てきた問題

戦略の中核なので厚く検証した。**解決したのではなく、明示した**という状態のものが多い。

1. **「カバレッジ0」と「データ欠損」が原理的に区別できない**（O01/O02/O19/O23）。
   日本の小型株の62%は予想データベースに行が存在しない。欠損を「カバレッジ0＝加点」と扱うと、
   **単にデータ整備の穴を買っている**ことになる。**このカテゴリ最大の実装上の壁。**
   対策は (a) ベンダーのユニバース定義で「収録済みだがカバレッジ0」と「未収録」を分ける、
   (b) 分けられないなら予想データに依存しない O03/O04/O08/O12 を主軸にする。
2. **O23（残差機関保有 × 予想分散）が自己矛盾している。** ネグレクトを測るカテゴリなのに、
   ネグレクトが最強の銘柄（無カバー）では予想分散が計算できず欠損する。
3. **O02（カバレッジ開始）と O19（カバレッジ減少）が、どちらも正のリターンを予測しうる。**
   前者は「発見の始まり」、後者は OSAP `ChNAnalyst` t=3.3 で「忘れられるほど上がる」。
   一見矛盾するが、**§1.9 が「相関する変数も統合せず両方残して縮小に任せる」と決めている
   理由の実例**になっている。
4. **O21（残差機関保有 × 特異ボラ）の符号が I04 単独と食い違う。**
   I04 は単独では負（高IVOLは劣後）だが、機関不在銘柄に限ると正になる（OSAP t=4.4）。
   **必ず交互作用項として持ち、I04 単独と併存させる。**
5. **O24（企業年齢）の符号の記述が紛らわしい。** `negative` は「年齢が大きいほど売り」ではなく
   「年齢が小さいほど劣後」の意。Phase 1 の実測で向きを確定させる要注意項目。
6. **O10 は加算ではなく乗数として使うのが本来の姿。** OSAP の RIO_* 系（O20-O23、t=2.5〜4.9）が
   それを実証している。§5 の初期重み 0.11 は加算分にすぎず、本命は N06 のような交互作用項。

### B カテゴリの検証で出てきた問題

7. **B41（Mohanram G-score）の発見が示したこと** — **バリュー株とグロース株で
   別の品質指標を使うという発想が 263AT に欠けていた。** B17（Piotroski）は低PBR群向けで、
   成長株に当てると現在の収益性の低さで全滅する。G-score は代わりに成長の安定性と
   無形投資を評価する。OSAP で t=9.1。
8. **分母ゼロの罠が3件**。B12（増分ROIC）は無投資企業で分母が消えて異常値が上位に来る。
   B01（ROE）は債務超過で符号が逆転する。B28（現金転換効率）は各年の比率を平均すると
   赤字年で壊れるので、**5年合計どうしで割る**必要がある。
   いずれも12問の q05 を通さないと見つからない類のもの。

### A / C カテゴリの検証で出てきた問題

9. **C カテゴリは符号が真っ二つに割れていた。** 売上・利益・FCF の成長は正、
   資産・資本・人員の成長は負。同じ「成長」という語で逆向きの現象を呼んでいたため、
   カタログ上は矛盾に見えていた。**アウトプットの成長は良く、インプットの成長は悪い**という
   整理をカタログ本体（§4-C の中心思想）に追記した。橋渡しするのは C08（ROIC × 再投資率）だけで、
   **B04（ROIC−WACC）が条件変数**になる。
10. **C38（自己資本比率の変化）で符号が水準と逆転する。** D02（水準）はゲートとして
    高い方が良いのに、C38（変化）は高い方が悪い（OSAP t=6.2、増資で上がるため）。
    **誤実装を誘発しやすい典型**なので Phase 1 で必ず実測確認する。
11. **A22/A23（自己バリュエーション位置）の正規化設定が誤っていた。** カテゴリ既定の
    `rank_sector` が当たっていたが、この2つは既に自己履歴で正規化済みの値。
    `rank_all` に上書きした（断面 z 化のみを行う）。
12. **分母ゼロ・解なしの罠がさらに5件。** A17（ネットキャッシュが時価総額超で実質PERが負）、
    A26/A42（DCF/RIM の解が存在しない）、C04（赤字期を含むと CAGR が定義できず、
    **ターンアラウンド銘柄が体系的に落ちる**）、C05（FCF の符号反転）、C29（無投資業種で発散）。
13. **C11/C12/C13/C15 は開示企業に強く偏る。** 汎用の C カテゴリに置いているが、
    実質は業種限定（U カテゴリ相当）。欠損を中立扱いすると、開示企業だけで順位がつく。

### M / N カテゴリの検証で出てきた問題

14. **インサイダー情報の鮮度が日米で桁違いだった**（catalog OQ-29）。
    米国 Form 4 は取引から2営業日、日本の売買報告書は**翌月15日まで（最長45日超）**。
    同じ M02-M04 でも、**米国では速報性のあるシグナル、日本では遅行指標**になる。
    現状のレジストリは `pit_lag_days` を1つしか持てないので、スキーマ変更が要る。
15. **M10 と N14（買収の予測）は DF-01 により検証手段が存在しない**（catalog OQ-30）。
    買収廃止銘柄の株価取得率は 0/15 = 0%。**バックテストから成功例だけが削除される。**
    親子上場解消とアクティビストという**個人の優位性の一角がここに集中している**だけに重い。
16. **N06（注目度調整PEAD）が自己矛盾していた。** SUE（コンセンサス）と O01（アナリスト数）を
    使うので、**注目度が最も低い銘柄で両方とも欠損する。** 仮説を検証したい対象で計算できない。
    → **N50 として、N04（発表日リターン）× O04（ニュース数）の予想非依存版を追加した。**
    価格とニュース数だけで計算でき、日本の無カバー小型株でも欠損しない。
    このレビューから生まれた唯一の具体的な解決策。
17. **N28（決算日クラスタリング）は欠損しない稀な指標。** 決算カレンダーだけで計算でき、
    日本は発表日が極端に集中する（3月期決算が5月上旬に数百社）ので効果が大きい可能性がある。
    N06 が使えない場面の代替として価値が高い。
18. **N31（期初会社予想の水準）は符号が直感と逆。** 「期初予想が弱気＝悪い会社」ではなく
    「弱気＝保守的＝上振れ余地」。ただし**本当に業績が悪い企業も低くなる**ので、
    N09（過去の保守性）で条件付けないと単に業績が悪い企業を買う。
19. **M05（インサイダー売り）を M02（買い）と対称に扱ってはいけない。** 売る理由は
    分散・納税・生活と多数あるが、買う理由は基本的に「安い」の1つ。
    符号を対称にすると、**株式報酬の多い成長企業を体系的に減点する**ことになる。
20. **N36/N37（リコール・サイバー攻撃）は報道量に依存するので、小型株で見逃す。**
    O カテゴリと逆方向に偏る＝**ネグレクト銘柄で悪材料を見逃す**という、
    リスク管理上まずい形の偏り。
