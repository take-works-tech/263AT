## 3. 動かす手順

### データを作る（初回・年1回）

```
.venv/Scripts/python.exe tools/fetch_prices.py --from-sec --period max   # 1-2時間
.venv/Scripts/python.exe tools/clean_price_glitches.py --write           # **分割誤調整を無害化**
.venv/Scripts/python.exe tools/build_pit_fundamentals.py --all           # 1時間
.venv/Scripts/python.exe tools/build_gc.py
.venv/Scripts/python.exe tools/build_sectypes.py

# パネル。**\| head や \| tail で切らない**（無出力・exit 0 で「完了」する）
.venv/Scripts/python.exe tools/build_panel.py \
    --start 2012-01-31 --end 2026-07-31 --horizons 250 --gates on --suffix _v2
```

### 測る（**最終構成**）

```
.venv/Scripts/python.exe tools/run_system.py --panel gate_v2 --horizon 250 \
    --cost-model real --cash-yield on --policy hysteresis \
    --entry-weight equal --min-position 0.015 --dump data/eq_final.json

.venv/Scripts/python.exe tools/measure_windows.py data/eq_final.json
```

**必ず対照も回す**（スコアの寄与を分ける唯一の方法）:

```
... 同じ引数 + --benchmark random --dump data/eq_final_rand.json
```

### 発注内容を見る

```
.venv/Scripts/python.exe tools/make_orders.py     # 既定が実費・等加重・1.5% になった
```

### 記録する（**最重要・年1回**）

```
.venv/Scripts/python.exe tools/record_generation.py --panel gate_v2 --top-n 56
.venv/Scripts/python.exe tools/record_generation.py --verify
.venv/Scripts/python.exe tools/record_generation.py --evaluate
```

**記録にランダム対照と等加重ユニバースが併記されるようになった**（第3号から）。
これで前向き評価が**ペア差**になり、判定の所要が **44年 → 3〜5年**に縮む。

## 7. このプロジェクトで繰り返し起きたこと

**測定を壊す欠陥は、通算で 20件を超えた。**
**そのほとんどは「良い成績」ではなく、おかしな数字か、
実物（発注内容・実費）を作ったときに見つかっている。**

| | 症状 |
|---|---|
| 順位表しか見ない | **上位3銘柄が社債だった**（13.5年ぶん測っても気づかない） |
| 目標値しか見ない | **投資比率 53%**・**参入枠の全滅**（実現値を出して初めて見えた） |
| 月末しか見ない | **最大DDが 15pp 浅く見える** |
| 一律のコスト | **実費は 5倍**（片道 0.22% → 1.19%） |
| `\| head` / `\| tail` | **無出力・exit 0 で「完了」する**（2026-08-29 に再発） |
| 元本比のコスト | **資産が増えると自動的に増える。成功が「コスト増」に見える** |

→ **数字が出たら、まず測り方を疑う。**
→ **「完了」と表示されても、行数を数える。**
→ **指標そのものが、変更の効果と交絡していないか確かめる。**
