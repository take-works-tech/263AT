## 0. 読み方（記法の定義）

### 符号（値が大きいときの向き）

| 記号 | 意味 |
|---|---|
| `+` | 値が大きいほど**買い**方向 |
| `-` | 値が大きいほど**売り**方向（＝小さいほど買い） |
| `∩` | 中庸が最良。両端が悪い → 非線形変換必須 |
| `∪` | 両端が良く中庸が悪い（稀） |
| `?` | 文脈依存。他パラメータとの交互作用で符号が決まる |

### 寄与度（買 / 売 の列）

| 記号 | 意味 |
|---|---|
| ◎ | 主力。重み大 |
| ○ | 有効。重み中 |
| △ | 補助。重み小、または閾値フィルタとしてのみ使用 |
| ✕ | そのスコアでは使わない |
| ▣ | **ハードゲート**。スコアに足さず、掛け算(0/1)で除外する |

### 実証度

| 記号 | 意味 |
|---|---|
| ★★★ | 複数国・数十年で再現。効果は縮小しているが方向は頑健 |
| ★★ | 再現性あり。ただし特定の市場・期間・サイズ帯に偏る |
| ★ | 証拠が限定的、または理屈先行の仮説。**自前検証が必須** |

> 前提として、公表アノマリーの **60〜65% は素朴な再現に失敗し、多重検定を考慮した t>2.78 の閾値では 80%超が消える**（Hou-Xue-Zhang 2020 ほか）。★★★でも「効果は当初報告の半分以下」を初期値と考えること。

### 有効ホライズン

`1M` / `3M` / `6M` / `1Y` / `3Y` / `5Y+` — そのパラメータが予測力を持つ期間。
本プロジェクトの主戦場は **6M〜5Y** なので、`1M` 中心のものは原則ノイズ扱い（ただし *執行タイミング* の微調整には使う）。

### データ源コード

| コード | 意味 | 概算コスト |
|---|---|---|
| `PX` | 株価・出来高（yfinance / Alpaca / J-Quants） | 無料〜 |
| `JQ` | J-Quants API（JPX公式・日本株） | 無料〜16,500円/月 |
| `EDI` | EDINET（有報・大量保有報告書） | 無料 |
| `TD` | TDnet（適時開示） | 無料(手)〜11,000円/月 |
| `SEC` | SEC EDGAR XBRL（companyfacts 等） | 無料 |
| `FIN` | 財務データ（JQ Premium / SEC / yfinance） | 無料〜 |
| `EST` | アナリスト予想（IFIS / Refinitiv / yfinance） | 無料(質低)〜高額 |
| `NEWS` | ニュース配信・RSS | 無料〜中 |
| `OPT` | オプションデータ（米国のみ実用的） | 無料〜中 |
| `MACRO` | 金利・為替・指数（FRED / e-Stat / 日銀） | 無料 |
| `CALC` | 他パラメータから計算 | — |
| `LLM` | LLMが生成 | トークン課金 |
| `SELF` | 自分の口座状態（保有・取得単価・税） | 無料 |

## 1. 設計の骨格

### 1.1 全体の流れ

```
 生データ
   ↓  [1] 特徴量化（Point-in-Time厳守）
 パラメータ x_k(i, t)
   ↓  [2] 断面正規化 → z_k(i, t)
 正規化スコア
   ↓  [3] カテゴリ集約 → C_c(i, t)
 カテゴリスコア
   ↓  [4] 重み付け合成 → S_buy / S_sell
 スコア
   ↓  [5] 期待リターン・リスクへの較正 → mu(i,h), sigma(i,h)
 期待値
   ↓  [6] ホライズン選択 h*(i)   ← ★保有期間の最適化はここ
   ↓  [7] ポジションサイジング（フラクショナルKelly）
 目標ウェイト w(i)
   ↓  [8] 現保有との差分 → 発注
 売買
```

### 1.2 断面正規化（[2]の中身）

生値は分布が歪み外れ値だらけなので、**ランク → 正規スコア変換**を標準とする。

```
z_k(i,t) = Phi_inv( ( rank_k(i,t) - 0.5 ) / N_t )
```

- `rank_k(i,t)` … 時点 t のユニバース内での順位（欠損を除いた N_t 銘柄中）
- `Phi_inv` … 標準正規分布の逆累積分布関数
- 外れ値に頑健 / 異なる単位の指標を加算可能 / 時点間で分布が安定、を同時に満たす
- **業種内ランク**と**全体ランク**を両方作り、どちらが効くかは検証で決める（バリュエーション系は業種内が原則）
- 符号が `∩` のものは、まず最適点からの距離 `-|x - x*|` に変換してからランク化する
- 欠損は「中央値で埋める」ではなく **欠損フラグを別パラメータとして持つ**（欠損自体が情報。小型株ほど欠損が多い）

### 1.3 スコア合成（[3][4]）

```
C_c(i,t) = SUM_{k in c} w_k * z_k(i,t) / SUM_{k in c} |w_k|      … カテゴリ内集約

S_buy(i,t)  = ( SUM_c W_c_buy * C_c(i,t) ) * Gate(i,t)
S_sell(i,t) = ( SUM_c W_c_sell * C_c(i,t) ) + H(保有状態) + Theta(テーゼ検証)
```

**`Gate(i,t)` は掛け算であって加算ではない。**
流動性不足・破綻懸念・会計不正疑いは、他のスコアがどれだけ良くても買ってはいけない。
加算にすると「安いから買う」で地雷を踏む。これがバリュートラップの正体。

```
Gate(i,t) = 1[流動性OK] * 1[破綻リスクOK] * 1[会計品質OK] * 1[上場維持OK] * 1[理解可能OK]
```

### 1.4 期待値への較正（[5]）

スコアをそのまま重み付けに使ってはいけない。**期待リターンに変換して初めて期待値計算ができる。**

```
mu(i,t,h)    = a_h + b_h * S_buy(i,t)          ← 過去データで h ごとに回帰して較正
sigma(i,t,h) = sigma_hist(i) * sqrt(h) * adj(レジーム)
```

`b_h` が有意に正でなければ、そのスコアは**期待値計算に使ってはいけない**。
（＝「スコアが高い銘柄は実際に上がった」を確認せずにサイジングするのは、単なる願望）

### 1.5 保有期間の最適化（[6]）★ユーザー要望の核心

保有期間を決め打ちしない。買う時点で**複数ホライズンを同時に評価**し、最良を選ぶ。

```
h in { 3M, 6M, 1Y, 2Y, 3Y, 5Y }

U(i,h)  = mu(i,h) - (lambda/2) * sigma(i,h)^2 - cost_roundtrip - tax(i,h)
                                                  ↑ h が長いほど1回あたりのコストは実質薄まる

h*(i)   = argmax_h  U(i,h) / h                  … 年率換算の効用が最大となる期間
conf(i) = U(i,h*) / ( U の h 方向の分散 )        … その期間推定がどれだけ尖っているか
```

- `h*(i)` を「想定保有期間」としてポジションに記録する
- **保有中も毎回 `h*` を再計算する**。`h*` が縮んで 0 に近づく＝売りシグナル
- `conf(i)` が低い（どのホライズンでも似た効用）銘柄は、そもそも確信が薄い → サイズを落とす
- 事後に「実現保有期間 vs 当初 h*」「h* 別の実現リターン」を記録し、次世代モデルの学習に使う
- これにより保有期間は *仮定* ではなく *推定量* になり、世代を追って較正される

### 1.6 ポジションサイジングとリスク選好の単一パラメータ化（[7]）

```
f_full(i) = mu(i, h*) / sigma(i, h*)^2              … フルKelly（比率）
w(i)      = clip( kappa * f_full(i), 0, w_max )     … フラクショナルKelly + 上限
            SUM w(i) <= 1 になるよう正規化
```

リスク/リターン選好を **rho ∈ [0, 1]** の1つのつまみで動かす（0 = 安定重視、1 = 期待値・非対称重視）。

| 制御対象 | 式 | rho=0 | rho=0.5 | rho=1 |
|---|---|---|---|---|
| Kelly分数 kappa | `0.15 + 0.35*rho` | 0.15 | 0.325 | 0.50 |
| 目標銘柄数 N | `round(22 - 14*rho)` | 22 | 15 | 8 |
| 1銘柄上限 w_max | `0.08 + 0.22*rho` | 8% | 19% | 30% |
| 右裾スコアの重み W_convex | `0.6*rho` | 0 | 0.30 | 0.60 |
| 最小時価総額（小型株許容） | `300億 * (1 - 0.9*rho)` | 300億 | 165億 | 30億 |
| バリュー vs 成長の傾き | `0.5 - 0.4*rho` | バリュー寄り | 中立 | 成長寄り |
| ハードストップ幅 | `ATR * (3 + 3*rho)` | 狭い | 中 | 広い |
| 想定保有期間の下限 | `3M + 9M*rho` | 3M | 7.5M | 12M |

> **なぜ rho が高いほどストップを広げるのか**
> 期待値重視＝右裾を取りに行く戦略では、狭いストップは「大勝ちする前のノイズ」で振り落とされる。
> 半年〜5年の保有では特に致命的。下方保護は**価格ストップではなく、テーゼ崩壊判定とポジション上限**で行う。

### 1.7 ヒステリシス（往復売買の防止）

```
買う:  S_buy > theta_buy      かつ  Gate = 1
売る:  S_sell > theta_sell
保持:  その間（theta_buy と theta_sell の間に広いデッドバンドを置く）
```

半年〜5年の保有を狙う以上、デッドバンドは**広く**。
目安：断面の上位15%で買い、上位50%を割って初めて売り検討に入る、程度。

往復コスト（手数料 + スプレッド + マーケットインパクト + 税）を年率で割り戻すと、
**年間回転率が 1.0 を超えた時点で、よほどの予測力がないと期待値が負に転じる。**
逆に言えば、長期保有設定は「予測力が弱くても勝てる」ための構造的な選択である。

### 1.8 「期待値重視・非対称ペイオフ」の正しい作り方 ⚠️

ユーザーの狙い（勝率は低くていい、1/10の大勝ちで全部カバー）は方針として正しい。
しかし**素朴に実装すると、学術的に最も期待値が低いと分かっている銘柄群を買うことになる。**

| やってはいけない実装 | なぜダメか |
|---|---|
| ボラティリティが高い銘柄を選ぶ | 特異ボラティリティ・アノマリー。高IVOL銘柄はむしろ低リターン |
| 直近に急騰した銘柄（宝くじ的）を選ぶ | **MAX効果**。過去1ヶ月の最大日次リターン上位decileは下位decileより月次1%超劣後 |
| 歪度が高い（右裾が長そうな）銘柄を選ぶ | 期待特異歪度と将来リターンは**負**相関。個人の宝くじ選好で既に割高 |
| 低位株・ボロ株の一発逆転を狙う | 上記すべてに該当。個人が最も負けるゾーン |

理由は共通で、**「右裾が長そうに見える銘柄」は個人投資家に人気があるため、既に高く買われている。**
右裾を「買う」のではなく「合成する」必要がある。

**正しい非対称ペイオフの作り方（4層で作る）**

| 層 | 手段 | 効果 |
|---|---|---|
| ① 銘柄選択 | 期待値が**正**の母集団（高ROIC × 再投資余地 × 小型 × 割安 × 無名）から選ぶ | 右裾が長く、かつ平均も正 |
| ② サイジング | Kelly比例。エッジが大きい銘柄に大きく張る | 少数の高確信銘柄に集中 |
| ③ 出口の非対称 | 損失側はテーゼ崩壊で切る。利益側は上限を置かない | ペイオフ関数がコール的になる |
| ④ 時間 | 勝ち銘柄を年単位で持ち続ける（複利） | 100倍株の平均到達期間は20〜25年。5年でも「複利の時間」が要る |

つまり **右裾は「そういう銘柄を買う」のではなく「そういう持ち方をする」ことで作る。**
Taleb のバーベルと同じで、宝くじを買うのではなく、宝くじ的ペイオフを *合成* する。

そして重要な点として、**現在のポートフォリオ全体（投信90% + 個別株10%）が既にバーベル構造**である。
個別株側は安全性を追う必要がなく、凸性（convexity）に全振りしてよい。
ただしそれは「危険な銘柄を買う」ではなく「上振れ余地が構造的に大きい銘柄に、耐えられるサイズで、長く張る」という意味である。

## 2. 買いスコアと売りスコアが違う7つの理由

| # | 非対称性 | 帰結（設計への反映） |
|---|---|---|
| 1 | **情報集合が違う** | 売り時には「取得単価・保有日数・当初テーゼ・含み損益・税務状態」という買い時に存在しない情報がある → カテゴリ R・S は売り専用 |
| 2 | **問題の型が違う** | 買い＝数千銘柄からの**ランキング問題**。売り＝保有10〜20銘柄の**個別判定問題**。断面正規化の母集団が違う |
| 3 | **コストの非対称** | 買わない機会損失は分散されるが、売却は**その場で手数料・スプレッド・税を確定**させる。売りの閾値は買いより高くあるべき |
| 4 | **ペイオフの非対称** | 上値は無限、下値は -100%。「損は早く、利は伸ばせ」＝売りスコアは**含み損側で敏感、含み益側で鈍感**にする（人間の本能の逆） |
| 5 | **時間の非対称** | 「買うか」は1回の判断。「売るか」は保有中**毎日問われ続ける**。毎日再評価するとノイズで売る → 再評価頻度自体を設計変数にする |
| 6 | **税の非対称** | 売却は課税イベント。**NISA口座では損益通算も繰越控除もできない**ため、NISA内の損切りは特定口座より実質コストが高い。口座種別で売り閾値を変える |
| 7 | **代替の非対称** | 売りは「この銘柄が悪い」だけでなく「**もっと良い銘柄がある**」でも起きる（機会費用）。買いスコアには存在しない比較項 |

### 買い / 売り の式（対比）

```
S_buy(i,t) =
      Wb_val   * C_valuation      … 割安か
    + Wb_qual  * C_quality        … 良い事業か
    + Wb_grow  * C_growth         … 伸びるか
    + Wb_mom   * C_momentum       … 市場が気づき始めたか
    + Wb_supp  * C_supply         … 需給が味方か
    + Wb_cat   * C_catalyst       … 再評価のきっかけがあるか
    + Wb_neg   * C_neglect        … まだ誰も見ていないか   ← 個人の優位性の源泉
    + Wb_llm   * C_llm_qualitative
    ──────────────────────────────
    * Gate(流動性・破綻・不正・上場・理解可能性)


S_sell(i,t) =
      Ws_deg    * ( S_buy(i, t_entry) - S_buy(i, t) )    … スコアの劣化量（水準ではなく変化）
    + Ws_thesis * Theta_broken(i, t)                     … 当初テーゼの崩壊度（LLM）
    + Ws_val    * C_overvaluation                        … 目標価格・内在価値の超過
    + Ws_risk   * delta_C_risk                           … 破綻/不正/流動性リスクの上昇
    + Ws_opp    * ( max_j S_buy(j,t) - S_buy(i,t) )      … 機会費用（乗り換え価値）
    + Ws_size   * | w_actual(i) - w_target(i) |          … サイズ乖離（リバランス）
    + Ws_time   * ( 1 - h_remain(i,t) / h*(i,t_entry) )  … 想定保有期間の消化
    - Ws_tax    * TaxCost(i, t)                          … 売却で確定する税・コスト（売りを抑制）
    - Ws_hold   * 1[含み益 かつ テーゼ健在]               … 利を伸ばすためのブレーキ
```

**最重要**: 売りスコアの主項は `S_buy` の *水準* ではなく ***劣化量*** であること。
水準で売ると、「買った時から常に上位10%だった超優良株」を一度も長く持てない。
長期複利を狙う設計では、これが致命的な差になる。

## 3. 投資の法則・鉄則とその数式化

投資の歴史で培われた法則を、263ATで**実装可能な形式**に落とす。

### 3.1 数学的・確率論的な法則（例外なく従うべきもの）

| # | 法則 | 内容 | 数式 | 263ATでの扱い |
|---|---|---|---|---|
| LAW-01 | 期待値 | 全ての判断は期待値で行う | `E[r] = SUM p_i * r_i` | **最上位の目的関数**。全パラメータは最終的にここに寄与するかで評価する |
| LAW-02 | 複利 | 幾何平均が支配する | `W_T = W_0 * PROD(1+r_t)` / `g = E[ln(1+r)]` | 算術平均でなく**対数リターンの期待値**を最大化する。これがKellyの根拠 |
| LAW-03 | 損失の非対称性 | -50%の回復には +100% が要る | `r_need = 1/(1-L) - 1` | 破綻確率の抑制を制約条件にする（Gate） |
| LAW-04 | Kelly基準 | 最適賭け比率 | `f = (b*p - q)/b` / 連続形 `f = mu/sigma^2` | kappa = 0.25〜0.5 の**フラクショナル**で使用。フルKellyは推定誤差で破綻する |
| LAW-05 | ボラティリティ・ドラッグ | 幾何平均 ≈ 算術平均 - sigma^2/2 | `g ≈ mu - sigma^2/2` | 高ボラ銘柄の期待値を自動的に割り引く。IVOLアノマリーの一部説明 |
| LAW-06 | 分散の数学 | 相関が低いほどリスクは減る | `sigma_p^2 = SUMSUM w_i w_j sigma_i sigma_j rho_ij` | 銘柄数を絞る（集中）代わりに、**残す銘柄間の相関を厳しく管理** |

### T. LLM派生パラメータ (31)

**中心思想**: LLMは「数字にできないものを数字にする」ために使う。
ただし **LLMを予測器として使ってはいけない**（「この株は上がりますか」は禁止）。
LLMは **抽出器・分類器・要約器** として使い、予測は数値モデルが行う。理由は §6 と §8 で詳述する。

出力は必ず**構造化（数値 + 根拠 + 確信度）**させ、根拠テキストを保存する。
根拠が保存されていないLLM出力は、後で検証できないため資産にならない。

## 6. LLM活用の設計

### 6.1 最重要原則: LLMを予測器にしない

```
✕ 悪い使い方: 「この銘柄は今後6ヶ月で上がりますか？」
○ 良い使い方: 「この開示文書から、影響額・売上比・恒久性を抽出せよ」
```

理由は3つある。

1. **ルックアヘッドバイアス** — LLMの学習データには、バックテスト期間の「その後」が含まれている。
   2020年のニュースを2026年のモデルに読ませると、そのニュースの結末を知った上で答えてしまう。
   GPT系のセンチメント分析で予測力が観測されても、その大部分が学習データ由来だったという指摘がある。
   **これは検出が難しく、しかも成績を派手に良く見せるため、263AT で最も危険なバグの形をしている。**
2. **較正されていない** — LLMの「70%の確率で上がる」は、実際の頻度と一致しない。
   数値モデルなら較正できるが、LLMの直接予測は較正手段が乏しい。
3. **再現性がない** — 同じ入力でも出力が揺れる。バックテストと実運用で挙動が変わる。

したがって LLM の役割は **抽出器・分類器・要約器** に限定し、
**予測は数値モデル（回帰・スコアリング）が行う。**

### 6.2 LLMの3つのレイヤー

| レイヤー | いつ動くか | 何をするか | モデル選択 | コスト感 |
|---|---|---|---|---|
| **L1: 実行時LLM** | 売買システムの稼働中（日次〜週次） | T01-T12 の抽出。決算・ニュース・開示のスコア化 | 安価で速いモデル。**プロンプトを固定してキャッシュ** | 銘柄数 × 更新頻度。**保有期間が長い設計なのでここは軽い** |
| **L2: 生成時LLM（Claude）** | 数ヶ月に1回 | 売買コードの生成・更新、パラメータ選択、仮説の提案 | 最高性能のモデル | 1回あたり大きいが年数回 |
| **L3: 改善時LLM** | 生成サイクルの後 | 実績の事後分析、なぜ効かなかったかの仮説生成、次世代への申し送り | 最高性能のモデル | 年数回 |

**保有期間が半年〜5年であることは、LLMコスト面で決定的に有利。**
デイトレなら L1 のコストが破綻するが、この設計なら
「保有20銘柄 × 週次再評価 + 新規候補100銘柄 × 月次スクリーニング」程度で十分回る。

### 6.3 L1 の設計ルール

| ルール | 内容 |
|---|---|
| **Point-in-Time プロンプト** | 入力に「今日は YYYY-MM-DD である。これ以降の情報は存在しないものとして答えよ」を必ず含める。ただし**これだけでは不十分**（6.5参照） |
| **構造化出力** | 必ず `{value, evidence, confidence, sources}` の形で返させる。根拠テキストを保存しないLLM出力は後で検証できない |
| **数値の範囲を固定** | 「0-10で採点」「-1〜+1」など。自由記述の数値は分布が安定しない |
| **単一の問いに分解** | 「この企業の魅力を教えて」ではなく「堀の類型を1つ選べ」「顧客集中度は何%か」と分ける |
| **キャッシュ** | 同じ文書に対する同じ問いは1回だけ。ドキュメントハッシュ + プロンプトハッシュでキー化 |
| **決定的にする** | temperature=0、プロンプトをバージョン管理し、バックテストと実運用で同一のものを使う |
| **フォールバック** | LLMが失敗した時は「中立値 + 欠損フラグ」。**LLMが落ちたら売買が止まる設計にしない** |
| **監査ログ** | 入力・出力・モデルID・プロンプトバージョン・日時を全件保存。**後から「なぜこの判断をしたか」を再構成できること** |

### 6.4 LLM派生パラメータの検証方法

数値パラメータと違い、LLM派生パラメータは**通常のバックテストで検証できない**。

| 手法 | 内容 | 信頼度 |
|---|---|---|
| **カットオフ後検証（唯一の本命）** | 使用モデルの知識カットオフ**以降**のデータだけで検証する | ◎ 唯一信頼できる |
| 前向き記録 | 今日から毎日 LLM 出力を記録し、将来のリターンと突合。**今すぐ始める価値がある** | ◎ 時間がかかるが確実 |
| 匿名化テスト | 企業名・日付・固有名詞をマスクして同じ判定ができるか | ○ 記憶依存の検出に有効 |
| プラセボテスト | 実際には起きなかった架空のニュースを混ぜ、同じように反応するか | ○ |
| 人間との一致率 | 少数サンプルで人間の判断と比較 | △ 予測力の証明にはならない |

> **実務的な帰結**: L1 の LLM パラメータは、最初は重み 0.03 程度（§5の初期重み案）に留め、
> カットオフ後検証で予測力が確認できた項目だけを段階的に引き上げる。
> **「LLMを使っているから賢い」は成績とは何の関係もない。**

### 6.5 「今日は YYYY-MM-DD である」だけでは防げないもの

日付制約を入れても、LLMは以下を漏らす。

- **銘柄名から結末を思い出す** — 「2015年のこの会社」と言われた時点で、その後の破綻や急騰を知っている
- **文体・用語から年代を推定する** — 日付を隠しても時代が分かる
- **一般化された知識** — 「このセクターは2020年代に伸びた」という知識が個別判断に染み出す

対策は **企業名の匿名化 + カットオフ後データでの検証** の二段構え。
匿名化すると T21（真の競合特定）のような機能が失われるので、
**パラメータごとに「匿名化して使うもの / 実名で使うもの」を分けて設計する。**

### 6.6 L2（Claudeによるコード生成）の設計

これが 263AT の本体。詳細は別ドキュメントに切り出す予定だが、原則だけ記す。

| 原則 | 内容 |
|---|---|
| **Claudeに渡すのは「材料」であって「答え」ではない** | このカタログ、検証結果、前世代の失敗記録を渡す。「勝つコードを書け」ではなく「この制約下で仮説を立てよ」 |
| **生成回数を予算管理する** | 生成した戦略の数 = 多重検定の試行回数。**カウントして Deflated Sharpe Ratio に反映する**（§8-3） |
| **事前登録** | 生成した戦略は、検証を実行する前に仕様を凍結・記録する。後から条件を変えたら別の試行として数える |
| **ホールドアウトの封印** | 最終評価用の期間には、生成時に一切アクセスさせない。Claudeのコンテキストにも入れない |
| **前世代の失敗を必ず渡す** | 「何を試して効かなかったか」の蓄積が、世代交代の唯一の資産 |
| **説明可能性を強制** | 生成された各パラメータに「なぜ効くと考えるか」の経済的理由を書かせる。**理由が書けないパラメータは採用しない**（データマイニング除け） |

## 8. 罠リスト

> このセクションは §4 のカタログより重要かもしれない。
> **パラメータ選びで負けるより、検証の設計ミスで負ける確率の方がずっと高い。**

### 8-1. ルックアヘッドバイアス（最頻出・最悪）

| 罠 | 具体例 | 対策 |
|---|---|---|
| 財務データの発表日を無視 | 3月期決算を4月1日から使ってしまう（実際の開示は5月） | **決算発表日ベースで参照する**。J-Quants/EDGAR は発表日を持っている |
| 訂正後データの使用 | yfinance の財務は最新の訂正済み値。当時の投資家は見られなかった | **PIT（Point-in-Time）データベースを自分で構築する**。取得時点のスナップショットを保存し続ける |
| 指数構成銘柄の遡及適用 | 現在のTOPIX構成銘柄で過去を検証する | 当時の構成銘柄リストを保持する |
| 上場廃止銘柄の欠落 | 現存企業だけで検証すると破綻企業が消える | **生存者バイアス（8-2）と同根** |
| LLMの知識 | §6.1 参照 | カットオフ後検証 + 匿名化 |
| 「その日の終値で買う」 | 引け値を見てから引けで買うことはできない | **翌日始値、または当日VWAPで約定させる** |

### 8-2. 生存者バイアス

- 上場廃止・倒産・被買収した銘柄を**必ずユニバースに含める**
- 特に日本の小型株は上場廃止が多く、これを除くと成績が劇的に良く見える
- 対策: 廃止銘柄の最終価格と廃止事由を記録した完全な銘柄マスタを作る（**構築コストが高いが、避けて通れない**）

### 8-3. 多重検定・データスヌーピング ← **263AT 最大のリスク**

このプロジェクトは構造的に「Claudeが大量の戦略を生成する」設計になっている。
つまり **試行回数が爆発的に増える。** 何もしなければ、必ず偽の勝ち戦略を掴む。

```
試行回数 N で、真のエッジがゼロでも
期待される最大シャープレシオ ≈ sqrt(2 ln N) / sqrt(T)

→ N=100 回試せば、真のエッジ 0 でも見かけ上シャープ 0.6〜0.8 の戦略が「見つかる」
```

| 対策 | 内容 |
|---|---|
| **試行回数を記録する** | 生成した戦略・試したパラメータの組み合わせを**全部数える**。捨てた案も数える。これを怠ると以下の補正が全部無意味になる |
| **Deflated Sharpe Ratio** | 試行回数と非正規性を補正した有意性を計算する。素のシャープを見て判断しない |
| **CPCV（組合せ的パージ済み交差検証）** | 単純な walk-forward より過剰適合検出に優れる。PBO（Probability of Backtest Overfitting）を算出する |
| **パージ + エンバーゴ** | 訓練期間と検証期間の間に空白を置く。ホライズンが重なるとリークする（**5年ホライズンなら5年のパージが要る**） |
| **ホールドアウトの封印** | 直近N年を完全に封印し、**最終判定に1回だけ使う**。2回使ったらもうホールドアウトではない |
| **経済的理由の必須化** | 全パラメータに「なぜ効くか」を書かせる（§6.6）。理由が書けないものは棄却 |
| **パラメータ数の予算** | 345個から選び放題にしない。**世代あたり採用パラメータ数の上限を決める**（例: 15個） |
| **成績の分布で判断** | 「この戦略が勝った」ではなく「生成される戦略群の期待値が正か」で判断する（README の L2 の考え方） |

> **経験則**: バックテストの成績が良すぎる時は、喜ぶのではなく**バグを探す**。
> 年率50%が出たら、それは発見ではなく、ほぼ確実にリークである。

### 8-4. 取引コストと流動性の過小評価

| 罠 | 対策 |
|---|---|
| 手数料だけ引いてスプレッドを無視 | 小型株では**スプレッドが手数料の数倍**。J04 を必ず引く |
| マーケットインパクトを無視 | S02（平方根則）を入れる。**入れないと小型株戦略は必ず過大評価される** |
| 建てられないサイズで検証 | J02（流動化日数）でフィルタしてから検証する。**「300万円で買える」ではなく「300万円で売れる」で判定** |
| 出来高ゼロ日に約定させる | J10。約定不能日をシミュレータで明示的に扱う |
| 値幅制限（日本）を無視 | ストップ高で買えない、ストップ安で売れない状況を再現する |

### 8-5. LLM 固有の罠

| 罠 | 対策 |
|---|---|
| LLMのルックアヘッド | §6.1、§6.5 |
| 出力の揺れ | temperature=0、プロンプトのバージョン管理 |

### 8-6. 設計思想上の罠

| 罠 | なぜ危険か |
|---|---|
| **宝くじ銘柄を「非対称ペイオフ」と勘違いする** | §1.8。**このプロジェクトで最も起きやすい失敗** |
| バリューだけで買う | バリュートラップ。Gate（D・E）を通していない安い株は、安い理由がある |
| 損切りルールを機械的にきつくする | 半年〜5年の保有では、ノイズで振り落とされる。**テーゼ崩壊で切る設計にする** |
| 買いスコアの水準で売る | 常に上位だった優良株を持ち続けられない。**劣化量で判断する**（§2） |
| マクロで銘柄を選ぶ | 予測が外れると全ポジションが同時に負ける。マクロはサイジングのみ（LAW-78） |
| パラメータを増やせば精度が上がると思う | 345個は**候補**であって採用リストではない。実際に使うのは10〜20個 |
| 過去に効いたファクターに全張りする | 公表アノマリーの80%超は多重検定閾値を超えない。**効果は当初報告の半分以下を初期値にする** |
| リバランス頻度を上げる | 回転率1.0超で期待値が負に転じうる（LAW-11） |

### 8-7. 運用上の罠

| 罠 | 対策 |
|---|---|
| バックテストと実運用でコードが違う | **同じコードパスを通す**。バックテストは「時間を巻き戻した実運用」であるべき |
| 途中で手を出す | 生成した売買システムを稼働中に手動で変えると、その世代の評価が不可能になる。**変更したら別世代として記録する** |
| 記録を残さない | 「なぜこれを買ったか」を保存していないと、売り判断（T25）ができず、改善もできない |
| NISAで損切りする | 損益通算も繰越控除もできない。**NISA枠には期待値が最も高い銘柄だけを入れる**（S04-S06） |
| 全体ポートフォリオを見ない | 90%は投資信託。個別株10%だけを最適化しても、全体では意味がないことがある（Q07-Q08） |

### 8-8. 「LLMを使っている」ことに満足する罠

LLM を使うと、成果物が賢そうに見える。だが**成績はコードの見た目とは無関係**。

原則: **すべてのLLM派生パラメータは、それを外した版と成績を比較して、勝った分だけ採用する。**
「LLMが良いことを言っている」は採用理由にならない。
