# 263AT 検証プロトコル v0.1 — 生成時点 PIT と機械的な売り

> **作成日** 2026-08-23
> **きっかけ** ユーザーからの3つの指摘。いずれも設計の欠陥を突いている。
> 1. 検証用の仕組みを用意していない
> 2. **検証時に集めるデータは、生成システムを動かすと想定した年月日より前に
>    公開されていた情報に厳しく限らなければ検証と言えない**
> 3. **生成される売買システムは全上場銘柄が対象なので、
>    LLM ではなく機械的なシステムを中心に置く**
> 4. **売りが特に重要。機械的な損失フィルタが要り、その閾値も最適化する**

---

## 0. まず認めること

**検証の仕組みは作っていなかった。**
ここまでで作ったのは「ある時点の断面スコアを正しく作る」層までで、
**時間を進めて売買し、成績を測る部分が無い。**

そして、もっと重い問題がある。

## 1. PIT には2つの水準がある — 私は片方しか守っていなかった

### 1.1 データ時点 PIT（実装済み）

    ある時点 t のスコアは、filed <= t のデータだけで作る

これは `src/facts.py` の `AsOf` で実装し、
`tools/smoke_phase1.py` で「後からデータを足しても過去の断面は変わらない」ことを確認した。
訂正の実例も測った（同じ期間の NI が1年半後に黒字→赤字に訂正される）。

**ここは守れている。**

### 1.2 生成時点 PIT（**守っていない**）

    時点 T に「売買システムを生成する」とき、
    **生成に使うすべての情報**が T より前に公開されていなければならない。

「生成に使う情報」とは:

| 何を | どこで決まるか | 今の状態 |
|---|---|---|
| どのパラメータを使うか | カタログ（770件） | **T より後の知識で決めている** |
| 各パラメータの重み | 縮小の推定 | 未実装 |
| ゲートの閾値 | §6 の UNIVERSE | **固定値を手で決めた** |
| 売りルールの閾値 | 未実装 | — |
| サイジングの係数 | §1.8 | **固定値を手で決めた** |

**データが PIT でも、システムの設計が未来を知っていれば検証にならない。**

### 1.3 私が既に持ち込んでいる漏れ — 正直に書く

**このカタログ自体が、2024年までの OSAP データを見て書かれている。**

- §1.9.8 で各パラメータに `t_replicated`（1963-2024 の再現 t）を書き込み、
  それを実装の優先順位に使った
- §1.9.7 で「G07 は G01 を控除すると alpha が消える」と実測し、買 ◎→○ に格下げした
- OQ-38/39 の塊の判定も 1926-2024 の相関で行った

**これらはすべて 2024年までを見た判断である。**
したがって:

> **2024年以前を対象にしたバックテストで良い成績が出ても、
> それは検証ではない。** カタログの設計自体に未来が入っている。

**対処は2つしかない。**

| 対処 | 内容 | 実行可能性 |
|---|---|---|
| (A) **前向き検証のみを信じる** | 2026-08-23 以降のデータでのみ成績を測る | **今日から可能。ただし年単位で待つ** |
| (B) 設計を凍結した上で、**設計に使っていない期間**で測る | OSAP は 2024年末まで → 2025年以降が未使用 | 期間が短い（実質1年半） |

**(A) を主、(B) を従とする。**
`tools/forward_log.py` を 2026-08-23 に開始したのはこのためだが、
**当時は LLM 出力の較正のためだけに考えていた。**
**実際にはシステム全体に必要だった。**

### 1.4 それでも過去の検証をする理由

過去の検証は**成績の推定には使えない**が、**別の目的には使える。**

| 目的 | 過去検証で分かるか |
|---|---|
| 期待リターンの推定 | **使えない**（設計に未来が入っている） |
| **実装のバグ検出** | **使える**（ルックアヘッドの混入、約定の不整合） |
| **回転率・取引コストの見積り** | **使える**（設計と独立） |
| **ドローダウンの形状** | 部分的に使える |
| **売りルールが機能するか** | **使える**（設計を訓練期間内に閉じれば） |

→ **過去検証は「成績を測る」ためではなく
「仕組みが壊れていないかを測る」ために回す。**

## 2. 生成時点 PIT を強制する仕組み

### 2.1 ウォークフォワードの単位は「システムの生成」

    for T in 生成日程（例: 3ヶ月ごと）:
        訓練窓 = [T - L, T)          ← **T を含まない**
        system = generate(訓練窓)     ← 重み・閾値・売りルールを訓練窓だけで決める
        for t in [T, 次の生成日):
            断面 = score(t, system)   ← filed <= t のデータのみ
            発注 = decide(断面, 保有)
            約定 = t+1 の始値

**`generate()` は訓練窓の外を一切参照できない。**
これをコードで保証する（引数として渡さない・アクセスを遮断する）。

### 2.2 最適化は訓練窓の中だけで行う

売りの閾値（損切り幅・トレーリング幅・保有期間上限）を最適化するが、
**最適化は訓練窓の中で完結させる。**

**さらに、訓練窓の中でも内側検証を切る。**

    訓練窓 = [T-L, T)
      └ 内側訓練 = [T-L, T-V)     ← 閾値の探索
      └ 内側検証 = [T-V, T)       ← 探索結果の選択

**内側検証まで使って選ぶと、訓練窓に過剰適合する。**
§1.9 で「選択は多重検定そのもの」と書いたのと同じ理屈が閾値にも当てはまる。

### 2.3 閾値は「粗く」探索する

損切り −8% と −8.5% を区別できるほどのデータは無い。

    損切り幅        : -30% / -25% / -20% / -15% / -10%
    トレーリング幅   : 無し / -30% / -20%
    保有期間上限     : 無し / 5年 / 3年 / 1年

**格子を粗く切り、選ばれた値が格子の端なら警告する**（範囲外に最適があるサイン）。

## 3. LLM を中心から外す — 設計の訂正

### 3.1 何が間違っていたか

T カテゴリ（LLM 派生）を45件用意し、§6 に LLM 設計を厚く書いた。
**しかし生成される売買システムは全上場銘柄（日米で1万4千銘柄）が対象である。**

| | 全銘柄に LLM を毎日回す | 機械的な計算 |
|---|---|---|
| コスト | **非現実的** | ほぼゼロ |
| 再現性 | **実行のたびに揺れる** | 決定的 |
| 過去検証 | **原理的に不可能**（§6.5） | 可能 |
| 監査 | 出力の理由が追えない | 式を追える |

→ **LLM は売買システムの中心に置けない。**

### 3.2 訂正後の役割分担

| 層 | 担当 | 頻度 |
|---|---|---|
| **売買システム本体** | **機械的な計算のみ**（A-S の定量パラメータ） | 毎日 |
| **メタシステム（生成）** | LLM が数ヶ月ごとにコードとパラメータを更新 | 数ヶ月に1回 |
| **例外的な精査** | 保有銘柄・購入候補の少数（20-50件）にのみ LLM | 週次程度 |

**LLM は「システムを作る側」に置き、「システムの中」には置かない。**
これがユーザーの当初の設計（メタシステム）と整合する。
私は T カテゴリを厚くしすぎて、**LLM をシステムの中に持ち込もうとしていた。**

### 3.3 T カテゴリの扱い

**削除はしない**（§1.9 の方針）。ただし:

- **T カテゴリは売買システム本体のスコアに入れない**
- **保有銘柄の精査（R07 テーゼ健在度）と、
  新規候補の最終確認にのみ使う** — 対象が数十件なら現実的
- **バックテストでは T カテゴリを一切使わない**（§6.5 の通り検証不能）
- したがって**バックテストの成績は「機械部分だけ」の成績**であり、
  それが実運用の下限になる

## 4. 売り — 機械的な損失フィルタ

### 4.1 なぜ売りが特に重要か

§2 で「買いと売りのスコアが違う7つの理由」を書いたが、
**実務上はもっと単純な理由がある。**

- **買いは見送れるが、売りは見送れない。** 保有している限り毎日判断が要る
- **263AT の設計は「9つが負けても1つで賄う」**なので、
  **9つの負けを小さく抑えることが1つの勝ちと同じくらい効く**
- Bessembinder（4%の銘柄が全リターンを作る）は
  **裏を返せば96%を早く手放す必要がある**ということ

### 4.2 売りルールの階層

**上から順に評価し、最初に該当したもので売る。**

| 順 | ルール | 種類 | 閾値 | 最適化 |
|---|---|---|---|---|
| 1 | **ゲート違反** | 強制 | D13 継続企業の前提 / E22 監査意見 / N23 整理監理 | しない |
| 2 | **流動性の消失** | 強制 | J01 を下回った | しない |
| 3 | **損切り** | 機械 | 取得来 −X% | **する** |
| 4 | **トレーリング** | 機械 | 最高値から −Y% | **する** |
| 5 | **時間切れ** | 機械 | 保有 Z 年 | **する** |
| 6 | **スコア劣化** | 機械 | 買いスコアが下位 W 分位に落ちた | **する** |
| 7 | **早期警戒の複合** | 機械 | B22/B23/B35 が同時悪化 + D17 悪化 | **する** |

**1と2は最適化しない。** 踏んではいけない地雷であって、
リスク許容度の問題ではない（§1.6 で rho を上場期間・監査意見に効かせないと決めたのと同じ）。

### 4.3 損切りは本当に有効か — 検証すべき仮説として扱う

**損切りは自明に良いものではない。**

- 平均回帰する銘柄では損切りは有害（H カテゴリの長期リバーサル）
- モメンタムがある銘柄では有効（G カテゴリ）
- **263AT は保有 6ヶ月-5年で、その区間は符号が反転する境界を跨ぐ**（OQ-31）

→ **「損切りを入れる／入れない」自体を最適化の対象にする。**
  「無し」を格子に含め、**無しが選ばれたらそれを受け入れる。**

### 4.4 一般的なリスク対策

| 対策 | 内容 | 実装 |
|---|---|---|
| **1銘柄あたりの上限** | 個別株枠の N% を超えない | サイジング |
| **業種あたりの上限** | 同一業種に M% を超えない | サイジング |
| **相関の上限** | 高相関の銘柄群に集中しない | サイジング |
| **月次損失の上限** | 月内の損失が K% を超えたら新規停止 | `guard.circuit_breakers` に実装済み |
| **1日の売買回転の上限** | 板を叩きすぎない | 執行 |
| **現金比率の下限** | ドライパウダー（P16） | サイジング |
| **キルスイッチ** | 手動で全停止 | `guard.check_kill_switch` に実装済み |

**月次損失の上限とキルスイッチは既に `src/guard.py` にある。**
残りをサイジング層で実装する。

## 4.5 測定を壊していた4つの欠陥（2026-08-24 追記）

15年ぶんのパネル（173ヶ月・73,888行）で初めて測ったところ、
**成績を測る仕組みそのものに4つの欠陥があった。**
どれも「データを増やす」では直らない。

### 欠陥1 — 実効サンプル数の取り違え

重なり合う将来リターンは独立ではない。90日の期間を月次でずらすと、
**隣接する観測は 3分の2 が同じ期間**を見ている。

    生成回数 165 に対し、独立な期間は **58.2 個**
    t 値 0.78（見かけ）→ **0.46（独立）**

Harvey-Liu-Zhu は **t > 3.0** を要求する。**まだ何も言えない。**

### 欠陥2 — 生存者バイアス（**無料データでは直せない**）

銘柄一覧を `company_tickers.json`（**今日のスナップショット**）から
作っているため、過去ほど「今日まで生き残った企業」だけを見ている。

| 年 | 当時の社数 | 今も登録 | 残存率 |
|---|---|---|---|
| 2012 | 7,333 | 2,389 | **32.6%** |
| 2016 | 6,399 | 2,848 | 44.5% |
| 2020 | 6,305 | 3,944 | 62.6% |
| 2025 | 6,671 | 5,747 | 86.1% |

上場廃止は倒産・業績不振が多いので**成績は上振れする。**
yfinance は廃止銘柄の価格を返さないので、**直せない。**
直せない以上、**測って出し続ける**のが唯一の正しい扱い。

**履歴を伸ばしたこと自体が、この問題を持ち込んだ。**
独立観測 4.7 個から 58.2 個へ増やす代償として、
残存率 86% の期間から 33% の期間へ手を伸ばしている。

### 欠陥3 — 最低株価のゲートが無かった

2020-10-31 の断面で **AITX の90日リターンが +10,729%**。
データの誤りではなく $0.0007 → $0.08 という実際の値動きである。

**しかしこの利益は取れない。** 板の刻み $0.0001 に対して株価が $0.0007
なので、**買って売るだけで 14% 以上が消える。**
ADV のゲートは通ってしまう（株数が膨大なので売買代金は立つ）。

    歪度 **−6.68**
    下位10%（16回）の合計 **−618.7%** に対し全体は +232.0%
    → **測定の2割が、取れない利益で決まっていた。**

閾値は**市場ごとに現地通貨**で持つ（US $1 / JP 100円）。
円換算した単一の閾値では機能しない —
**日本の 200円 は普通の銘柄だが、同額の $1.3 は仕手株の領域である。**

**rho では動かさない。** 低位株を買うかどうかは「リスク許容度」の
問題ではなく、**利益そのものが実現しない**という問題だから。

### 欠陥4 — ロングショートの指標でロングオンリーを評価していた

**263AT はロングオンリーである。** 買うのは上位分位だけで、
下位分位は**一度も持たない。**
それなのに評価指標を「上位 − 下位」にしていた。

上の −206.9% は、**下位分位にサブペニー株が入って +250% に化けた**
からで、**上位分位は何も悪くない。**
**買わない銘柄の値動きで、買う銘柄の評価が壊れていた。**

欠陥3 とは独立した問題である。ゲートを直しても、指標が間違っていれば
測っているものが違う。主指標を **上位 − 全体平均**に変えた。

さらに、**上位20%（120銘柄）は実際に持つ集中度ではない。**
3M円で最小ポジション2%なら持てるのは数十銘柄で、
**上位の1〜2銘柄で結果が決まる。**
`--top-n`（既定20）で実運用の集中度も並べて出す。

### この4つから引き出す原則

> **成績が出たときに最初に疑うのは、戦略ではなく測り方である。**

4つのうち3つは「良い成績」ではなく**異常な数字**（−206.9%、歪度 −6.68）
から見つかった。**数字がおかしいときにデータを疑う習慣がなければ、
どれも見つからなかった。**

そして欠陥3と4は、**どちらも「買わない銘柄」に関するものだった。**
ユニバースの端にあるものは、買わないから安全だと思いがちだが、
**分位の境界と平均の計算には入ってくる。**

## 4.6 通しの検証の結果（2026-08-24）

15年（2012-2026、173ヶ月、9,631銘柄）を通して、
**買い → 売り → サイジング → 執行 → 損益**まで回した最初の結果。

### 対照実験 — 最低株価ゲートは「儲け」ではなく「信頼度」を上げる

同一の走査結果に対し、**ゲートの有無だけ**を変えた4本。

| 条件 | 上位20%−平均 | 上位20銘柄−平均 | 入替率 | コスト/年 | 正味超過/年 | **t（独立）** |
|---|---|---|---|---|---|---|
| ゲート有 / 90日 | +1.94% | +7.11% | 32% | 0.65% | +7.20% | **6.49** |
| ゲート有 / 250日 | +6.06% | **+20.52%** | 27% | **0.20%** | +8.65% | **5.52** |
| ゲート無 / 90日 | +1.60% | +6.49% | 34% | 0.69% | +5.80% | 3.95 |
| ゲート無 / 250日 | +7.00% | +21.65% | 29% | 0.21% | +10.02% | 2.73 |

**250日ではゲートを入れると正味が下がる（+10.02% → +8.65%）のに、
t は倍になる（2.73 → 5.52）。**
取れない利益を除いた分だけ、残ったものが確かになった。

**回転率は想定の3分の1だった**（実測 27-34%、従来は100%と仮定）。
**250日保有はコストを 0.65% → 0.20% に下げる。**
設計の「6ヶ月〜5年」がコスト面から裏付けられた。

### **機械的な損切りは有害だった**

§4.3 で「損切りは本当に有効か — 検証すべき仮説として扱う」と書いた件の答え。

| 損切り | 年率 | 最大DD | 発動 | | トレーリング | 年率 | 最大DD |
|---|---|---|---|---|---|---|---|
| −10% | +7.42% | **−12.3%** | 238 | | −15% | +6.92% | −13.5% |
| −15% | +7.49% | −14.3% | 115 | | −25% | +7.41% | −14.7% |
| −20% | +7.38% | −15.8% | 62 | | −35% | +8.04% | −13.2% |
| −30% | +7.72% | −14.8% | 16 | | −50% | +7.99% | −13.2% |
| −50% | +8.05% | −13.2% | 1 | | | | |
| **なし** | **+8.09%** | −13.2% | 0 | | **なし** | **+8.09%** | −13.2% |

**ルールが効かなくなるほど基準に近づく、という単調な形。**
閾値の選び方の問題ではなく、**ルールそのものが有害**である。
**最適値を探した結果が「使わないこと」だった。**

理由は買いスコアとの衝突である。
**採用パラメータに G04（直近1ヶ月リターン、符号 −）が入っている。**
つまりこのシステムは**短期で下げた銘柄を買う。**
損切りは**短期で下げた銘柄を売る。**
発動するたびに、買いスコアが「買え」と言った銘柄を捨てていた。

唯一の例外は **−10% の浅い損切りが最大DDを −13.2% → −12.3% に下げた**こと。
**年率 0.67pp を払って DD を 0.9pp 買う取引**である。
個別株は全体の1割なので、**全体で見れば DD 1.32% → 1.23%。**
期待値を優先する設計方針とは整合しない。**リスク許容度の問題なので、
これは私が決めることではない。**

保有上限は無害だった（1年 +7.79% / 2年 +8.15% / 3年 +8.03% / なし +8.09%）。

### **パラメータがシステムを黙って止めることがある**

`min_trade_frac`（この比率未満の調整はしない）を振ったところ:

| 値 | 年率 | 約定 | コスト | 
|---|---|---|---|
| 0.005 | +8.09% | 1,984 | 25.0% |
| 0.01 | +8.25% | 1,620 | 24.0% |
| 0.02 | +10.25% | 1,294 | 23.6% |
| **0.05** | **+0.50%** | **121** | 2.4% |
| **0.10** | **+0.10%** | **2** | 0.1% |

**0.05 以上ではシステムが取引をやめる。**
1銘柄の目標ウェイトは 2% 前後なので、調整幅の下限がそれを上回ると
**一度も売買が起きない。** それでもエラーは出ず、
**「CAGR +0.50%」と表示されるだけ**である。

→ **成績が「取引しなかった結果」に化ける。**
  約定回数が生成回数を下回ったら警告を出すようにした。

0.02 の +10.25% は**採用しない。**
13.5年で独立観測 20.9 個しかないのに、閾値を触って 2.2pp 動いた。
**滑らかな反応ではなく崖である。** 過剰適合の形をしている。

### 絶対水準は信用しない

+8% という数字には、**上振れ方向の交絡が2つ**残っている。

1. **生存者バイアス** — 2012年の残存率 32.6%
2. **カタログ自体のルックアヘッド** — 2012〜2026年は設計にとって全部が in-sample

**信用できるのは相対比較だけである。**
ゲートの効果、回転率の実測、保有期間の効果、売りルールの単調性 —
これらは同一データ・1条件だけの違いなので、交絡の影響を受けにくい。

## 4.7 目的関数が設計方針とずれていた（2026-08-24）

### 指数と比べていなかった

**同じ期間（2012-11-30 〜 2026-05-29、13.5年）:**

| | 年率 |
|---|---|
| このシステム | **+8.09%** |
| **SPY（S&P500）** | **+13.18%**（配当込みなら約 +15%） |
| BRK-B（バフェット） | +13.29% |
| QQQ | +19.61% |

**指数に年5pp、配当込みなら7pp 負けている。**
「+8% は上振れしている、実力は3〜5%」という議論を延々としていたが、
**上振れを引く前の時点で VOO に負けていた。**
比較対象を持たない測定は、いくら精密でも意味がない。

**バフェットの 19.8%/年 は 1965-2023 の全期間の数字**で、
この13.5年では +13.29% = S&P500 とほぼ同じである。
Frazzini-Kabiller-Pedersen (FAJ 2018) によれば、その超過の大部分は
**BAB（低ベータ）+ QMJ（クオリティ）× 約1.6-1.7倍のレバレッジ**で説明でき、
レバレッジの源泉は**短期国債より安い保険フロート**である。
レバレッジを外すと銘柄選択そのものは年率12%程度、Sharpe 0.79。
**個人が複製できるのは「長く持つ」だけ。**

### 平均を測っていた。設計方針は期待値だった

263AT の方針は「勝率ではなく期待値」「個別株は全体の1割なので、
9割が負けても残りが何十倍になれば勝つ」である。
**ところが測っていたのは分位の平均リターンだった。**

**平均は「少し良い銘柄を大量に持つ」戦略を高く評価する。**
10倍株を1本当てる能力は、平均にはほとんど現れない。

そして**実装も平均を取りに行く作りだった。**

| | 実装 | 方針に沿うなら |
|---|---|---|
| 保有期間 | 月次で入れ替え（実測入替率27%） | 数年〜10年 |
| 勝った銘柄 | 目標ウェイトまで**削る** | **削らない** |
| 目的関数 | 分位の**平均**超過 | **右の裾の出現率** |

**Kelly サイジングは上がった銘柄を目標比率まで戻す。
つまり10倍になる途中で何度も売る。** 方針と正反対だった。

### 右の裾を測ったら、スコアには裾を当てる力があった

**5年後の倍率**（十分位別、17時点・35,204観測）

| 十分位 | 中央値 | 平均 | 2倍+ | 5倍+ | **10倍+** | 半減 |
|---|---|---|---|---|---|---|
| **上位1** | 1.49 | **2.12** | 35.8% | 6.5% | **1.33%** | **10.0%** |
| 5 | 1.20 | 1.54 | 20.7% | 2.5% | 0.5% | 11.8% |
| 10 | 0.51 | 0.96 | 13.5% | 2.2% | 0.4% | 49.7% |
| 全体 | 1.17 | 1.55 | 22.2% | 3.0% | 0.6% | 18.2% |

**上位十分位の10倍株出現率はそれ以外の 2.5倍**（3年後では 3.7倍）、
**半減率は最も低い**（10.0% 対 18.2%）。

決定的なのは **上位十分位の平均 2.12 に対し中央値は 1.49** —
**平均を押し上げているのは裾である。**

**上位十分位を等加重で5年持てば 2.12倍 = 年率 16.2%** で SPY を上回る。
**+8.09% しか出なかったのは、この裾を取りに行っていなかったから。**

### 銘柄数には下限がある

上位十分位は1時点あたり約350銘柄。300万円では持てない。
少数を引くと**平均は同じでも、裾を引き当てられるかは運**になる。

    10倍株 1.33% → 50%の確率で1本引くには **約53銘柄**
    5倍株  6.5%  → 50%の確率で1本引くには **約11銘柄**

**「9割負けても1割が何十倍」を成立させるには引く回数が要る。**
集中しすぎると裾を取り逃し、分散しすぎると裾の寄与が薄まる。

### この測定での生存者バイアス

**倒産・上場廃止した銘柄は価格が取れないので最初から入らない。**
→ **半減率 10.0% は過小、10倍株率 1.33% は過大。**
**上位とその他の比（2.5倍）は信用できるが、絶対水準は信用できない。**

## 4.8 目標の変更 — 「指数に勝つ」を外す（2026-08-24）

### なぜ外すか

**理由1: 達成していない。**
修正後のパネルで通しの検証をやり直した結果（13年）:

    システム 年率 **+8.3%** / sd 7.6%
    SPY      年率 **+13.7%** / sd 13.8%
    相関 0.70

**理由2: 判定に44年かかる。**
年次超過の標準偏差（トラッキングエラー）は **10.0%** で、
仮に超過が +3%/年あったとしても t>2 に **44年**、t>3 に **99年**必要。
**生きているうちに「指数に勝った」と証明できない。**

**理由3: 負けている原因は、スコアではなく土俵である。**

    ユニバース等加重（250日先の平均）  +7.6% → 年率 **+11.4%**
    SPY を同じ250日先で測ると          +9.1% → 年率 **+13.5%**

**ユニバースそのものが指数に 2.1pp 負けている。**
そこにコスト 1.7% が乗るので、スコアの寄与（無作為 +0.77% に対し
+8.3%）を足しても届かない。
**2012-2026 は巨大テックが指数を牽引した期間**で、
等加重の小型中心という土俵は構造的に不利だった。

**土俵を大型株中心に変えるのは意味がない** —
それは「指数に近いものを高いコストで作る」ことになる。

### 新しい目標（**5年で判定できるもの**）

| 旧 | 新 |
|---|---|
| 指数に勝つ | **5年でマイナスにしない** |
| （なし） | **指数が下げた年に耐える** |

**どちらも実測で支持されている。**

**5年でマイナスにしない**

| 期間 | 最悪 | 中央値 | 最良 | マイナスの窓 |
|---|---|---|---|---|
| 3年 | **+3.2%** | +8.4% | +12.1% | **0 / 12** |
| 5年 | **+3.2%** | +8.1% | +12.6% | **0 / 10** |

単年では 2018年 −0.5%、2022年 −9.0% があるが、
**3年以上の窓は13年間で一度もマイナスにならなかった。**

**指数が下げた年に耐える**

| 年 | SPY | システム | 差 |
|---|---|---|---|
| 2015 | −0.8% | **+8.2%** | +9.0% |
| 2018 | −6.3% | **−0.5%** | +5.8% |
| 2022 | **−19.5%** | **−9.0%** | **+10.5%** |
| 平均 | −8.9% | **−0.5%** | +8.4% |

**SPY がマイナスだった3年すべてで上回った。**
ただし**サンプルは3回しかない。**

### ポートフォリオ全体への効果

個別株を w、残りを SPY とした場合:

| w | 年率 | sd | 最悪年 | シャープ相当 |
|---|---|---|---|---|
| 0% | +13.68% | 13.75% | −19.5% | 0.99 |
| **10%** | +13.14% | 12.92% | −18.4% | **1.02** |
| 30% | +12.06% | 11.34% | −16.3% | **1.06** |

**混ぜるほどリスク調整後は改善する。** 年率は下がるが、
ボラティリティと最悪年がより大きく改善する。

### **この改善は、誤差と区別できない**

**シャープ 0.99 と 1.02 を、独立観測21個で区別することはできない。**
そして上振れ方向の交絡（生存者バイアス、カタログのルックアヘッド）が
残っているので、**真の値はもっと低い可能性がある。**

言えるのはここまでである。

- 「マイナスにしない」は **3年以上の窓で 12/12**（比較的頑健）
- 「指数に勝つ」は**達成しておらず、判定にも44年かかる**
- 分散効果は **SPY 下落年3回すべてで確認**（サンプル3回）
- リスク調整後の改善は**正の方向だが、誤差と区別できない**

## 4.9 パラメータを増やす方向は行き止まりだった（2026-08-24）

### 予測を先に書き、当てた

L01（再現 t=9.93）を足しても成績が動かなかったので、
N02（再現 t=9.32）を足す前に**予測を書いた。**

> **N02 追加後の正味超過は +8.5% 前後のまま、変化は ±0.5pp 以内**と予測する。
> 理由は実効本数が既に飽和しているため。
> **外れたら、飽和の見立てが誤っていたことになる。**

| | 10本 | 29本 | +L01 | **+N02/L02** |
|---|---|---|---|---|
| 正味超過/年 | — | +8.48% | +8.51% | **+8.50%** |
| t（独立） | — | 4.48 | 4.47 | **4.44** |
| **実効本数** | 4.5 | 8.0 | — | **4.8 / 27** |

**変化は −0.01pp。予測どおりだった。**

### 決定的なのは実効本数である

**27本を候補に入れて、実質 4.8 本しか使われていない。**
L01 と N02 という**カタログ最強クラスの2本を足しても、
実効本数はむしろ減った**（8.0 → 4.8）。
λ が上がり、より強く縮小して吸収されただけである。

### このセッション全体での推移

| | |
|---|---|
| パラメータ | 10本 → **37本** |
| 実効本数 | 4.5 → **4.8**（ほぼ不変） |
| 正味超過 | ほぼ **+8.5% で不変** |
| **独立観測** | **21個のまま** |

**再現 t が 9 以上の本を2つ足しても動かない。**
これは「もっと良いパラメータを探せば良くなる」という道が
**閉じている**ことの、最も強い証拠である。

**制約は情報ではなく、証拠である。**
独立観測21個で推定できる自由度は、**5本程度が上限**だった。

### 残っている、意味のある方向

| | 内容 | 制約 |
|---|---|---|
| **前向き記録** | **交絡のない証拠を貯める唯一の経路** | 3〜5年 |
| 実運用 | 現在の構成で実際に動かす | いつでも可能 |
| 日本株 | 米国以外の**独立な**検証データ | 費用（保留中） |

**「パラメータを増やす」はこの一覧に無い。**

## 6. 最初の実測（2026-08-23）

`tools/run_backtest.py` を米国株 1,383 銘柄・2024-10 〜 2025-03 で回した。
**成績は測っていない**（設計に未来が入っているため）。測ったのは仕組みである。

### 6.1 ルックアヘッドの検査 — 通った

| 検査 | 結果 |
|---|---|
| 同じ日の断面を2回作って値が変わらないか | **差 0 銘柄** |
| 期間を最後まで進めた後、最初の日の断面が変わらないか | **差 0 銘柄** |

→ **as-of は効いている。** データ時点 PIT は守られている。

### 6.2 回転率とコスト — **これが最も重要な実測**

月次リバランス、ユニバース 646 銘柄、保有 14-15 銘柄。

| スプレッド（片道） | 年率コスト | **計画アルファ 2.5% に占める割合** |
|---|---|---|
| 5 bps | 0.29% | 12% |
| **25 bps** | **0.88%** | **35%** |
| 50 bps | 1.61% | **64%** |

**回転率は年率 2.9 倍（片道）。**

→ **小型株の現実的なスプレッド（25-50bps）では、
コストが計画アルファの 35-64% を食う。**

OQ-24 で「コストの仮定が結論を決める」（月次 0.03-0.10% で 7/9 が正、
0.25% では 1/9）と書いたことが、**自分のパイプラインで再現された。**

**含意は3つ。**

1. **リバランス頻度を落とす。** 月次は高すぎる。四半期以上を既定にすべき
2. **流動性の下限を上げる**（rho を下げる）。ただし
   **263AT の狙い（機関が見ていない小型株）と正面から衝突する**
3. **回転率そのものを最適化の目的関数に入れる。**
   成績だけを見て閾値を選ぶと、回転率が跳ねて手取りが減る

### 6.3 実装の欠陥が3つ出た

**(1) データの取得範囲を銘柄の属性と取り違えていた。**
上場後経過月数を「取得できた価格のバー数 ÷ 21」で概算していたため、
**2年分しか落としていない状態では全銘柄が「上場3.3ヶ月」に見えて全滅した**
（181/181 が TOO_YOUNG）。
→ **偽の近似をやめ、`Thresholds.require_age=False` で明示的に切る。**
  切ったことが除外内訳に現れないので、読む人が「効いていない」と分かる。

**(2) ユニバース全体に Kelly を配っていた。**
619 銘柄に配ると各 0.16% になり、**最小ポジション 2% を全員が下回って
保有が2〜3銘柄まで落ちた。**
→ **`select_top(n_target)` を追加。**
  n_target は明示しなければ `投資比率 ÷ 最小ポジション`（= 45）から逆算する。
  **N を明示的に選ばないと、制約が勝手に決めてしまう。**

**(3) 勘定の順序が逆だった。**
執行の後に評価していたため、**t+1 で約定した後の保有を t の価格で評価**していた。
シグナルにルックアヘッドは無いが、**エクイティカーブが嘘になる。**
→ 評価 → 売り判定 → 断面 → サイジング → 執行 の順に直した。

### 6.4 まだ正しくないところ

- **上場期間のゲートが切れている**（上場日を持っていない）
- **監査意見・継続企業の前提を True で仮置きしている**（SEC から取っていない）
- **円換算レートが固定値**（本来は available_at 時点のスポット）
- **合成が等加重**（§1.9 の縮小推定を実装していない）。
  等加重は OQ-24 で「単独では失敗する」と出ている方法なので、
  **成績が悪く出るのは想定内**
- **日本株を含んでいない**（J-Quants / EDINET が未登録）

## 7. 縮小推定をウォークフォワードで回した（2026-08-23）

`src/shrink.py` + `tools/build_panel.py` + `tools/run_shrink_wf.py`。
米国株 646 銘柄・10 パラメータ・2024-11 〜 2026-01（パネル 9,521 行）。

### 7.1 3つ目のルックアヘッドを見つけた — **ラベルが未来**

データ時点 PIT（`filed <= t`）も生成時点 PIT（設計が T 以前）も守った上で、
**さらに1つ条件が要ることに気づいた。**

    観測の日付が T-30日、将来リターンの期間が90日
      → その観測のリターンが確定するのは T+60日
      → **T の時点ではまだ分からない**

**日付が過去でも、ラベルが未来なら訓練に使ってはいけない。**

    使ってよい条件 = 観測日 < T **かつ** 観測日 + H <= T

`usable_at()` として実装した。**これを落とすと、
as-of をどれだけ厳密に守っても未来が入る。**

### 7.2 結果 — **正直に書く**

| 保有期間 | 生成回数 | 差が正 | 年率の粗 | 年率コスト | **年率の正味** | **独立観測数** | **t（独立）** |
|---|---|---|---|---|---|---|---|
| 90日 | 11 | 4/11 | +1.97% | 2.43% | **−0.47%** | **4.7** | **0.12** |
| 250日 | 3 | 3/3 | +23.66% | 0.88% | **+22.78%** | **1.7** | **2.55** |

**250日の +22.78% を成果として受け取ってはいけない。**

- **独立な観測は 1.7 個しかない**（観測期間 427日 ÷ 250日）
- 重なり合う将来リターンは独立ではない。
  250日の窓を月次でずらせば、隣接する観測は **92% が同じ期間**を見ている
- 独立数で計算した t は 2.55。**Harvey-Liu-Zhu の t > 3.0 に届かない**

→ **`run_shrink_wf.py` に実効サンプル数の警告を実装した。**
  見かけの観測数と実効数を取り違えると、**偶然を発見と誤認する。**

### 7.3 それでも読み取れること

**(1) λ が格子の上端に張り付き続ける。**
格子を 300 → 10,000 まで広げても上端を選ぶ。
**データがシグナルをほとんど支持していない**という診断そのもの。

**(2) 実効本数は 2.8〜3.1 / 10。**
等加重（実効 10）でも1本集中（実効 1）でもない中間で、
**OQ-24 の「非負 ridge は soft selection として働く」が自分のデータで再現された。**

**(3) 重みが乗るのは A04（S/P）と B02（ROA）に偏る。**
F24 と A06 は**一度も 0 でない重みを得なかった**（0/11、0/5）。
→ カバレッジが低い（F24 70%、A06 40%）ことと無関係ではない。
  **欠損を 0 として扱う以上、カバレッジの低いパラメータは
  推定上も不利になる。** §4 の「欠損は z=0 + フラグ」の副作用。

**(4) コストが決定的。**
90日保有で年 2.43%、250日保有で年 0.88%。
**保有期間を延ばすだけでコストが 1/3 になる。**
263AT の設計（保有 6ヶ月-5年）は、**この理由だけでも正しい。**

### 7.4 結論として言えること / 言えないこと

**言える:**
- 仕組みは動く。3種類のルックアヘッドを構造で防げている
- **コストは保有期間で桁が変わる。** 短期リバランスは成立しない
- 縮小は soft selection として機能している

**言えない:**
- **アルファがあるかどうか。** 独立観測が 2〜5 個では何も分からない
- **10 本は 770 本の代表ではない。** 日本固有・LLM 派生・保有状態が全部欠けている
- 期間が米国の特定の 14ヶ月に限られている

→ **前向き検証（2026-08-23 開始）を年単位で待つ以外に、
この問いに答える方法は無い。** これは §1.3 で書いた通りである。

## 4.10 前向き記録を始めた（2026-08-24）

### なぜこれが最重要か

現在の全結論には**2つの上振れ交絡**が残っている。

1. **生存者バイアス** — 2012年の残存率 32.6%。廃止銘柄は最初から入らない
2. **カタログ自体のルックアヘッド** — パラメータの選定と符号を
   2024年までの OSAP を見て決めた。**2012-2026 は設計にとって全部 in-sample**

**どちらも過去データでは除去できない。**
除去できるのは「**今日決めて、将来を待つ**」ことだけである。

    今日 T に上位N銘柄を記録する
      → **T の時点で未来は存在しない**
      → 250日後、記録と実際のリターンを突き合わせる
      → **交絡ゼロの証拠が1個できる**

### 書き換えを仕組みで防ぐ

**追記のみ・ハッシュ連鎖**（`knowledge.py` と同じ）。
**過去の記録を1件でも直すと `verify()` が落ちる。**

**そして `tools/run_tests.py` がコミット前に毎回検証する。**
実測で確認した:

    銘柄を1つ差し替える → **終了コード 1（コミットが止まる）**
    復元する           → 終了コード 0

**規律を人に任せない。**
5年後の自分が「あの銘柄は入れていたはず」と書き換えられる状態では、
**証拠にならない。**

### 運用

    .venv/Scripts/python.exe tools/record_generation.py            # 記録
    .venv/Scripts/python.exe tools/record_generation.py --verify   # 連鎖の検証
    .venv/Scripts/python.exe tools/record_generation.py --evaluate # 実現値と突合

**記録の間隔は年1回でよい**（§4.9 の通り、独立な情報は年に1つしか増えない）。
**ただし1日遅らせれば、検証の開始も1日遅れる。**
