## 1. J-Quants

> **2026-08-23 訂正。** この節は当初「Free プランで検証には十分」と書いていた。
> **誤りだった。** 実際に確認したところ、
> **Free では日本株の財務情報が一切取れない。** 下に事実を書き直す。
> あわせて、**認証方式も V1 のトークン方式で書いていたが、V1 は
> 2026-06-01 に終了している。** パスワードはもう使わない。

### 1.1 認証は API キー1本 — **パスワードは要らない**

```
x-api-key: <APIキー>
```

キーは J-Quants のダッシュボード **「設定 » API キー」** で発行する。
`.env` に書くのは**この1行だけ**である。

```
JQUANTS_API_KEY=発行されたキー
```

**メールアドレスもパスワードも API には使わない**（ダッシュボードに
ログインするためだけのもの）。`.env` に書く必要はない。

旧 V1 はメールアドレス + パスワード → リフレッシュトークン（1週間）
→ ID トークン（24時間）という方式だったが、
**V1 は 2026-06-01 に終了した。** `/v1/token/auth_user` は 403 を返す。

### 1.3 263AT にとって何を意味するか

| 用途 | Free で足りるか |
|---|---|
| 日本株のユニバース構築（3,713銘柄・東証33業種） | **足りる** |
| 日本株の株価・モメンタム・ボラティリティ | **足りる**（2年窓） |
| **日本株の財務（A/B/C/E カテゴリ）** | **足りない**（財務情報が無い） |
| **K01-K09（信用残・空売り）** | **足りない**（Standard 必要） |
| **K17/M23/K35/M11（日本固有の優位性の中核）** | **足りない**（Standard 必要） |
| 6ヶ月〜5年の保有期間の検証 | **足りない**（2年窓では足りない） |

→ **Free でできるのは「日本株の価格系パラメータの実装と疎通確認」まで。**
  **検証には足りない。**

### 1.4 **Standard は EDINET 由来のデータを含む**

政策保有株式・大株主状況・大量保有報告書は EDINET の開示から作られているが、
**J-Quants の Standard プランに含まれている。**
→ **EDINET の API キー取得が難航している場合、Standard を契約すれば
  日本固有の中核（K17 / M23 / K35 / K18 / M11）はそちらで埋まる。**
  EDINET の API キーが要るのは、残りの D13 / E22 などのゲートと有報の記述項目。

### 1.5 いつ課金するか

**先に有料プランを契約しないこと。** ただし上の表の通り、
**Free では日本株の検証が成立しない**ので、
「Free で検証 → 見込みが立てば課金」という当初の筋書きは成り立たない。

順序としては:

1. **Free で疎通確認**（キーが通るか、東証33業種が付いてくるか、株価の形）
2. 米国株（SEC DERA・無料）で**検証の枠組みを完成させる**
3. 日本株を本格的に入れる段で **Light（¥1,650）か Standard（¥3,300）を判断する**

**Standard の ¥3,300/月 は、K カテゴリ（信用残）と日本固有の優位性の
中核をまとめて解放する。** 263AT の設計では、ここが日本株の分岐点になる。

## 2. EDINET

### 2.1 手順

1. https://api.edinet-fsa.go.jp/api/auth/index.aspx?mode=1 を開く
   （EDINET のトップからも辿れる: https://disclosure2.edinet-fsa.go.jp/ ）
2. メールアドレスを登録して API キーを発行
3. **`.env` に1行足す**

```
EDINET_API_KEY=発行されたキー
```

### 2.2 EDINET で何が取れるか

**263AT のゲートに直結するものが多い。**

| 取れるもの | 対応するパラメータ | なぜ重要か |
|---|---|---|
| **継続企業の前提に関する注記** | **D13（ゲート）** | 現在 True で仮置きしている |
| **監査意見** | **E22（ゲート）** | 同上 |
| 有価証券報告書のリスク項目 | T08 / E14 | 企業が自ら書いた悪材料 |
| 政策保有株式 | K17 / A18 / M23 | **日本固有の優位性の中核** |
| 大量保有報告書 | M11 | アクティビストの参戦 |
| 役員報酬・従業員数 | M18-M20 / W02 | |

**`tools/run_backtest.py` は現在、監査意見と継続企業の前提を
`True` で仮置きしている。** EDINET が繋がれば、
`universe.py` は `None` を「適正」に丸めない設計なので、
**データを入れるだけでゲートが正しく厳しくなる。**

### 2.3 EDINET の登録でつまずいたときの調べ方（2026-08-23 実測）

**キー発行画面が真っ白になる**事象を追った記録。同じ症状のとき、
この往復を繰り返さないために残す。

#### 分かっている事実

| 確認したこと | 結果 |
|---|---|
| **EDINET の認証は Azure AD B2C** | `fsaedinetauth.b2clogin.com` / ポリシー `B2C_1_APIManagement` |
| `index.aspx?mode=1` の応答 | Cookie の有無によらず **302 で B2C へ**。EDINET 側は正常 |
| `mode=3` など不正な値 | 「パラメータが正しくありません」 |
| パラメータ無し | 「パラメータが足りません」 |
| **不正な `code` で戻った場合** | **302 → `/error.html`**「現在使用できない状況になっております」 |
| EDINET API v2 本体 | キー無しで叩くと **401**。**障害ではなく稼働中** |
| 対応環境（ESE140009） | **Windows 11 + Edge / Chrome**。解像度 1366×768 以上 |

→ **EDINET はエラー時に必ず文字を出す。**
  **真っ白は、EDINET の既知のエラー画面のどれでもない。**

#### 紛らわしいもの（原因ではない）

**`Unrecognized Content-Security-Policy directive 'prefetch-src'`**
B2C が送る CSP に `prefetch-src 'self'` が入っているが、
**このディレクティブはどのブラウザも実装していない**（仕様の草案どまり）。
「知らないので無視した」という報告であって、**何もブロックしていない。**
コンソールで最初に目に入るので原因と誤認しやすい。

**メンテナンス告知**
閲覧サイト（`weee0020.aspx`）に常時出ている。
**実測時の窓は 2026-08-29 08:00 〜 08-30 08:00 JST** で、当日とは無関係だった。
**告知の存在ではなく、日時を読むこと。**

#### 見るべきところ

`authorize` の応答の `location` に **`code=` が付いていれば、サインインは成功している。**
その場合、Cookie も JavaScript も問題ない。**問題はその後の戻り先にある。**

Network を見るときは **「Preserve log（ログを保持）」を必ず ON にする。**
転送のたびにログが消えるため、**入れないと favicon のような
後続リクエストしか残らず、肝心の転送の連鎖が見えない。**

#### 疑わしいもの

`x-ms-cpim-sso` Cookie が付いていると、**B2C はログイン画面を出さずに黙って通す。**
**メール登録を完了する前に作られた古いセッションで通っている**と、
B2C はコードを発行するが EDINET 側はキー発行対象と認識せず、
**エラーにもならず画面だけ出ない。**

→ `chrome://settings/content/all` で `edinet` と `b2clogin` の
  データを両方消してからやり直す。**ログイン画面が実際に出るのが正常。**

#### フィルタリングソフトを使っている場合（仕様書 ESE140009 §1-1）

```
https://disclosure2.edinet-fsa.go.jp/
https://disclosure2dl.edinet-fsa.go.jp/
https://repository.secomtrust.net/
```

**この一覧に `b2clogin.com` が無い。**
金融庁の文書は閲覧サイトのみを対象にしているため。
**API キーの発行だけは Microsoft のドメインを通る**ので、
フィルタを使っているなら `fsaedinetauth.b2clogin.com` も自分で許可する必要がある。

## 3. `.env` の扱い — **これだけは守ってほしい**

```
JQUANTS_API_KEY=（ダッシュボードの「設定 » API キー」で発行した値）
JQUANTS_PLAN=Free
EDINET_API_KEY=（EDINET で発行した値）
```

| 規約 | 状態 |
|---|---|
| **`.env` を git に入れない** | `.gitignore` 済み |
| **コミット前に自動検査する** | `tools/security_check.py` が pre-commit で走る |
| **ログに秘密を出さない** | `src/credentials.py` の `mask()` を通す |
| **パスワードを他で使い回さない** | **ユーザーの作業。J-Quants 専用のパスワードにすること** |

**実際に security_check.py は一度、私のテスト用文字列を秘密と判定して
コミットを止めたことがある**（`api_key=` に続く十分な長さの文字列を
直書きした行）。仕組みとしては動いている。

**この文書自身も一度止められた。** 上の事案を説明するために、
止められた文字列をそのまま書いていたため。
**検査器を緩めるのではなく、文書の方を書き直した。**
検査器が例外を覚えるほど、検査器は弱くなる。

### 確認方法

```
python src/credentials.py --status
```

**何が設定済みで何が足りないかを、秘密を出さずに表示する。**
