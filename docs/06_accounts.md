## 0. 結論 — 両方とも無料で作ってよい

| | 費用 | 何が要るか | 制約 |
|---|---|---|---|
| **J-Quants** | **¥0（Freeプラン）** | メールアドレス・パスワード | **データが12週間遅延する** |
| **EDINET** | **¥0** | メールアドレス | 遅延なし |

**12週間遅延は、検証には全く問題ない。**
実運用に移す段階で有料プランを検討すれば十分である。

## 1. J-Quants

### 1.1 制約を先に理解する

J-Quants の公式FAQ に次の記載がある（2026-08-23 に確認）。

> **「できません。無料プランではデータは12週間遅延して配信されます。」**

つまり:

| 用途 | Freeプランで足りるか |
|---|---|
| **過去データでの検証** | **足りる**（12週間前より古いデータが取れる） |
| **パラメータの実装とカバレッジ測定** | **足りる** |
| **前向き記録の開始** | **足りる**（12週間遅れで確定していく） |
| **実際の発注** | **足りない**（12週間前の株価では売買できない） |

→ **今の段階（検証）では Free で正しい。**
実運用に移す判断をした時点で、有料プラン（ライト等）を検討する。

**先に有料プランを契約しないこと。** 検証で見込みが立つ前に払う理由が無い。

### 1.2 手順

1. https://jpx-jquants.com/ を開く
2. 「無料で始める」から登録（メールアドレス・パスワード）
3. 届いたメールで認証
4. **プロジェクト直下に `.env` を作り、次の2行を書く**

```
JQUANTS_MAILADDRESS=登録したメールアドレス
JQUANTS_PASSWORD=登録したパスワード
```

### 1.3 認証の仕組み（コード側で処理済み）

J-Quants は2段階の認証を使う。

    メールアドレス + パスワード
      → リフレッシュトークン（1週間有効）
      → ID トークン（24時間有効）
      → 各 API を叩く

**トークンの更新はコード側で自動化してある**（`src/jquants.py`）。
`.env` にメールアドレスとパスワードを書けば、あとは触らなくてよい。

## 2. EDINET

### 2.1 手順

1. https://api.edinet-fsa.go.jp/api/auth/index.aspx?mode=1 を開く
   （EDINET のトップからも辿れる: https://disclosure2.edinet-fsa.go.jp/ ）
2. メールアドレスを登録して API キーを発行
3. **`.env` に1行足す**

```
EDINET_API_KEY=発行されたキー
```

### 2.2 EDINET で何が取れるか

**263AT のゲートに直結するものが多い。**

| 取れるもの | 対応するパラメータ | なぜ重要か |
|---|---|---|
| **継続企業の前提に関する注記** | **D13（ゲート）** | 現在 True で仮置きしている |
| **監査意見** | **E22（ゲート）** | 同上 |
| 有価証券報告書のリスク項目 | T08 / E14 | 企業が自ら書いた悪材料 |
| 政策保有株式 | K17 / A18 / M23 | **日本固有の優位性の中核** |
| 大量保有報告書 | M11 | アクティビストの参戦 |
| 役員報酬・従業員数 | M18-M20 / W02 | |

**`tools/run_backtest.py` は現在、監査意見と継続企業の前提を
`True` で仮置きしている。** EDINET が繋がれば、
`universe.py` は `None` を「適正」に丸めない設計なので、
**データを入れるだけでゲートが正しく厳しくなる。**

## 3. `.env` の扱い — **これだけは守ってほしい**

```
JQUANTS_MAILADDRESS=you@example.com
JQUANTS_PASSWORD=xxxxxxxx
EDINET_API_KEY=xxxxxxxx
```

| 規約 | 状態 |
|---|---|
| **`.env` を git に入れない** | `.gitignore` 済み |
| **コミット前に自動検査する** | `tools/security_check.py` が pre-commit で走る |
| **ログに秘密を出さない** | `src/credentials.py` の `mask()` を通す |
| **パスワードを他で使い回さない** | **ユーザーの作業。J-Quants 専用のパスワードにすること** |

**実際に security_check.py は一度、私のテスト用文字列を秘密と判定して
コミットを止めたことがある**（`api_key=` に続く十分な長さの文字列を
直書きした行）。仕組みとしては動いている。

**この文書自身も一度止められた。** 上の事案を説明するために、
止められた文字列をそのまま書いていたため。
**検査器を緩めるのではなく、文書の方を書き直した。**
検査器が例外を覚えるほど、検査器は弱くなる。

### 確認方法

```
python src/credentials.py --status
```

**何が設定済みで何が足りないかを、秘密を出さずに表示する。**

## 4. 登録後に私ができること

`.env` が揃った時点で、次が動く。

| 作業 | 効果 |
|---|---|
| 日本株の銘柄マスタと株価の取得 | **ユニバースが 3,713 銘柄増える** |
| 東証33業種での業種内正規化 | §4.1 の設計がそのまま動く |
| **D13 / E22 のゲートを実データで埋める** | 仮置きが消える |
| K01-K09（信用残・空売り残） | **日本固有。米国に対応が無い** |
| K32/K33 の代替検討 | 四季報は J-Quants に無いので別途 |

**日本株が入って初めて、263AT の設計（日米両建て・日本固有の優位性）が
検証の対象になる。** 現状の検証は米国だけで、
**カタログで「日本の中核戦略の生命線」と書いたもの（K32/K33、K17、A15）が
1つも入っていない。**
