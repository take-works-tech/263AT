## 2. 米国 — SEC EDGAR（実測）

### 2.1 PIT は可能か → **可能**

`companyfacts` の各ファクトに **`filed`（提出日）が入っている。**

```json
{"start":"2015-09-27","end":"2016-09-24","val":215639000000,
 "accn":"0000320193-18-000145","fy":2018,"fp":"FY","form":"10-K","filed":"2018-11-05","frame":"CY2016"}
```

利用可能なキー: `accn / end / filed / form / fp / frame / fy / start / val`

> ### ⚠️ ここに最大の罠がある（実測で定量化した）
>
> 同じ `(tag, 期間)` が**何度も提出される。しかも値が変わる。** AAPL で実測した結果:
>
> | タグ | ユニーク期間 | うち複数回 filed | **値が変わった期間** |
> |---|---|---|---|
> | `NetIncomeLoss` | 123 | **112（91%）** | 5 |
> | `NetCashProvidedByUsedInOperatingActivities` | 67 | 52（78%） | 4 |
> | `StockholdersEquity` | 72 | 46（64%） | 3 |
> | `Assets` | 70 | 18（26%） | 3 |
>
> 極端な例:
> - **`NetIncomeLoss` の `end=2009-06-27` は 1,229百万ドル と 1,828百万ドル の2つの値を持つ（差 48.7%）**
>   — AAPL の売上認識基準変更に伴う遡及修正。丸め誤差どころの話ではない
> - `StockholdersEquity` の `end=2020-09-26` は **10回** 提出されている（+34日 〜 **+1,133日**）
> - `Assets` の `end=2008-09-27` は 36,171 と 39,572（9.4%差）
> - `CFO` の `end=2016-09-24` は 65,824 と 66,231（0.6%差）
>
> **複数回提出は例外ではなく常態（NetIncomeLoss で91%）であり、値の差は丸め誤差ではない。**
>
> #### 正しい PIT ルール
> ```
> value_as_of(tag, period, t) = filed <= t を満たす行のうち、filed が最大のものの val
> ```
> これが「時点 t の投資家が見ていた値」である。訂正が t より前に出ていれば訂正後を見ているし、
> t より後なら見ていない。
>
> **やってはいけないのは、`filed <= t` の条件を付けずに最新行を採ること。**
> pandas で素直に `groupby(["tag","end"]).last()` と書くとこれになり、
> **AAPL 2009年6月期の純利益で 48.7% ずれる。** バックテストは静かに良くなる方向に狂う。
>
> 保守的な代替として「常に最古の filed（当初報告値）を使う」という選択もある。
> 訂正情報を一切使わないので漏れは絶対に起きないが、実際の投資家より情報が少ない前提になる。
> **263AT は as-of 方式を既定とし、Z14 のテストで `filed <= t` を assert する。**

### 2.2 遡及可能年数 → **2009年7月から**（XBRL 義務化）

## 5. 期間の制約 — ここが一番厳しい

catalog §1.9.2 の有効サンプル数の表を、**実測した実際のデータ期間で埋め直す。**

断面の有効幅は `N_eff_cs ≈ N/(1+(N-1)ρ)`、残差平均相関 ρ=0.01（楽観）で約98。

| データ源 | 使える年数 | 5Yホライズンの独立期間 | N_eff | N_eff / 661 | 判定 |
|---|---|---|---|---|---|
| **OSAP（米・CRSPベース）** | 1970-2024 ≈ **54年** | 10.8 | 約 1,060 | **1.6** | 辛うじて何か言える |
| **自前 EDGAR（米）** | 2009-2026 ≈ **17年** | 3.4 | 約 330 | **0.5** | **推定不能** |
| **J-Quants Premium（日）** | 最大 **20年** | 4.0 | 約 390 | **0.6** | **推定不能** |

同じ計算を 1Y ホライズンで行うと、OSAP 54 期間 → N_eff 約 5,300 → **8.0**。ここなら推定できる。

> ### 設計への帰結（重要）
> **「保有期間 半年〜5年、期間もパラメータとして最適化する」という要件のうち、
> 3〜5年の部分は、どの無料データでも直接推定できない。**
>
> 選択肢は3つある。
>
> | 案 | 内容 | 評価 |
> |---|---|---|
> | A | 3M〜1Y で係数を推定し、長期は §1.5 の `U(i,h)` で**外挿**する | **推奨。** 構造上すでに可能な設計になっている |
> | B | 有料データ（CRSP / Compustat）で期間を伸ばす | 個人には高額。300万円の運用に見合わない |
> | C | 5Y ホライズンを諦め、最長 2Y にする | 税繰延と取引コストの利点を失うので勿体ない |
>
> A を採る場合、**「長期の係数は短期からの外挿であり、データで直接裏づけられていない」ことを
> 明示的に記録する**（レジストリの `horizon` と、期待リターン較正 §1.4 の信頼区間に反映する）。

## 7. 残課題と必要なアクション

### 7.0 DF-01 の実測（2026-08-23）— 無料の株価では検証できない

「yfinance では廃止銘柄が取れない」と書いていたが**実際には試していなかった**ので、試した。

| 廃止事由 | 株価が取れた銘柄 | 取得率 |
|---|---|---|
| **買収・TOB** | 0 / 15 | **0%** |
| 破綻 | 4 / 12（BBBY, FRCB, SBNY, YELLQ） | 33% |

取れなかった例: TWTR, ATVI, VMW, SGEN, HZNP, ABMD, CERN, CTXS, ZNGA, NUAN, XLNX, MXIM, WORK, SPLK, PXD

> #### 偏りの方向が最悪である
>
> **買収された銘柄は痕跡なく消える。** 破綻銘柄は破綻後も店頭で値が付くものが残るので部分的に取れる。
> つまり無料データでバックテストすると、**「TOBで30〜40%のプレミアムを得た勝ち銘柄」だけが
> 系統的に削除され、「破綻して紙屑になった負け銘柄」は残る。**
>
> 263AT はこれが直撃する。**M10（アクティビスト標的スコア）、N14（TOB期待スコア）、
> K18（親子上場）は、まさに買収を予測するために設計されている。**
> これらの検証は、無料の株価データでは**構造的に不可能**である。
>
> 単なる「データが足りない」ではなく、**狙っている戦略の勝ちパターンだけが見えない**という
> 特異な欠落。結論: **yfinance / Yahoo はバックテストに使えない。** 現在値の確認用に限る。

残る選択肢:

| 案 | 内容 | 状況 |
|---|---|---|
| Alpaca | 無料登録。廃止銘柄の履歴が取れるかは未検証 | **ユーザーの登録待ち** |
| 有料データ（Sharadar / Norgate / CRSP） | 廃止銘柄を含む。月数十ドル〜 | 300万円の運用に対する費用対効果を要判断 |
| 日本株に軸足を移す | J-Quants が廃止銘柄を含むかは未検証 | **ユーザーの登録待ち** |
| 買収予測系（M10/N14/K18）の検証を諦める | 他のパラメータだけで進める | 個人の優位性の一角を失う |


### 7.0b DF-02 の実測（2026-08-23）— yfinance は分割調整済みの価格を返す

Phase 0 の実装（`src/bars.py`）を実データで通す煙テスト（`tools/smoke_phase0.py`）で発見した。

**yfinance は `auto_adjust=False` を指定しても、分割については既に調整済みの価格を返す。**
未調整なのは**配当だけ**である。ドキュメントには明記されていない。

実測での確認 — 6758.T（ソニーG）の 2024-09-27、**5分割**:

```
2024-09-25   2755.0
2024-09-26   2848.0
2024-09-27   2861.0     ← 分割日。5分の1に落ちていない
2024-09-30   2777.5
```

生の価格なら分割日に約 570 円へ落ちるはずが、落ちていない。

#### 何が起きたか

`Stock Splits` 列の 5.0 をそのまま `bars.Bar.split_factor` に渡し、
`bars.adjust()` で遡及調整したところ、**二重調整**になった。

| 銘柄 | 二重調整時の最大 \|日次リターン\| | 修正後 |
|---|---|---|
| 6758.T（5分割） | **161.4%** = ln(5) | 12.7% |
| 9984.T（4分割） | **139.4%** = ln(4) | 20.7% |

#### なぜ重大か

**これは §8 の「バックテストでは検出されず、成績を良く見せる方向に効く」誤りそのものである。**

- 分割日に **+161% の偽の急騰**が立つ
- **モメンタム（G）はその偽の急騰を買う**
- 直後の系列では偽の急落に見えるので、**リバーサル（H）もそれを買う**
- **どちらも「よく当たる」ように見える**

しかも**分割は好業績企業に多い**ので、
**偽のシグナルが good な銘柄に集中する** — バックテストの成績が systematically 良くなる。

さらに悪いことに、**この誤りは銘柄数が増えるほど目立たなくなる。**
数千銘柄のうち年に数%しか分割しないので、
全体の統計を見ても異常に見えない。**個別に見ないと気づけない。**

#### 対処

1. **アダプタで `split_factor=1.0` を固定する。**
   分割イベント自体は記録するが、調整には使わない。
2. **`bars.detect_split_misadjustment()` を追加した。**
   分割日をまたぐリターンが `|r| ≈ ln(split_factor)` になっていれば警告する。
   符号で「二重調整（正）」と「未調整（負）」を区別する。
3. **新しいデータ源を繋いだら必ずこれを通す。**
   データ源ごとに「分割調整済みか」が違い、しかも明記されていないため。

#### 追記（同日）— 検出器の閾値を2回作り直し、バグを1つ見つけた

1,383 銘柄で `verify()` を回したところ **309銘柄（22%）**が引っかかった。多すぎる。

| 判定基準 | 引っかかった銘柄 |
|---|---|
| `|日次リターン| > 60%` なら調整漏れを疑う | **309 / 1383** |
| 分割日の **±3日以内**に限定 | 146 |
| **変動幅が `ln(分割比率)` と一致**するものに限定 | 145 |
| **`detect_split_misadjustment` のバグを修正** | **19** |

**(1) 60% 閾値は極小型株に対して厳しすぎた。**
AREB / ASBP / ATEK を調べると、**分割と無関係な本物の値動き**だった
（0.065 → 1.1 が1日で起きる）。

**(2) 「分割日の近く」だけでも足りない。**
**株式併合は暴落に伴って起きる**（上場維持基準に抵触したから併合する）ので、
近さだけでは本物の暴落と区別できない。
→ **変動幅が `ln(分割比率)` とちょうど一致するか**が唯一の識別子。

**(3) `detect_split_misadjustment` に株式併合を検出できないバグがあった。**
`expected = math.log(split_factor)` としていたが、
**併合（比率 < 1）では ln が負**になる。
`abs(|r| - 負の数)` は閾値を超えないので、**併合の調整漏れを一切検出できなかった。**
`abs()` を付けて修正した。**米国の極小型株は併合を繰り返すので、無視できない見落とし。**

残った19件のうち4件は **yfinance が実際に調整していない銘柄**だった。
→ **yfinance の分割調整は普遍ではない**（約0.3%）。これも検査が要る理由。

#### 副産物 — 株式併合の回数は F18 の定義を見直す材料になる

AREB は**18ヶ月で5回**併合していた（1:9 → 1:25 → 1:20 → 1:20 → 1:100）。
1,383 銘柄のうち **48銘柄（3.5%）が直近2年で1回以上**併合している。

F18（株式併合）は「実施の有無」のフラグとして定義していたが、
**1回なら整理、5回なら希薄化の死の螺旋**で意味が全く違う。
→ **F18 を「有無」から「直近N年の回数」に見直すべき。**
`src/prices.py` に `reverse_splits()` として実装した。

#### 一般化 — データ源の癖は「明記されていない」ことが本質

DF-01（買収廃止銘柄が消える）と DF-02（分割が既に調整済み）は、
どちらも**ドキュメントを読んでも分からず、実データを見て初めて分かった。**

> **無料データ源については「何が保証されているか」ではなく
> 「何を自分で検査するか」で設計する。**

`src/bars.py` に検査を組み込み、`tools/run_tests.py` から
常に走らせるようにしたのはこの方針による。
`src/guard.py`（安全装置は LLM に生成させない）と同じ考え方で、
**静かに損をする層には、必ず自動検査を付ける。**

#### 問題1 — 期間の混在が例外ではなく常態だった（81%）

**NI の期間と TA の期間で年が違う企業が 4,693 / 5,783 社（81%）。**

```
例: cik=1800  NI=2023-12-31（通期） / TA=2024-06-30（時点）
```

spec §1.3 では B02（ROA）を **分子 TTM・分母 AVG（期首期末平均）** と定めたのに、
煙テストでは**通期 NI と単一時点の TA** を混ぜていた。

**これを「近似」と書いて済ませてはいけない量である。**
81% ということは、**ほぼ全社で分子と分母の時点がずれている。**
決算期が3月・6月・9月とばらける企業ほど誤差が大きくなるので、
**業種によって系統的な偏りが出る。**

→ **TTM の合成（直近4四半期の積み上げ）と B/S の期首期末平均は、
Phase 2 の最初の作業にする。** 後回しにできる近似ではない。

#### 修正した（`src/periods.py`、同日）

DERA を17四半期（ファクト 383万件）まで広げて実装・実測した。

| | 近似版 | **厳密版** |
|---|---|---|
| B02（ROA）を作れた企業 | 6,072 | **6,847** |
| うち期間ずれ | **4,975（81%）** | **0** |

**厳密にした方が社数が多い。**
近似版は「450日以内の通期 NI」を要求するのに対し、
厳密版は四半期を積み上げるので**カバーがむしろ広い。**
→ **妥協が精度も網羅も両方失っていた**という珍しい例。

**Q4 の復元が 6,368 社（93%）で必要だった。**
10-K は通期しか出さないので、**第4四半期単体はほぼ存在しない。**
`Q4 = 通期 − (Q1+Q2+Q3)` で復元しなければ、
**TTM は93%の企業で作れなかった。**

|ROA|>1 は 12.5% で近似版（12.6%）とほぼ変わらなかった。
→ **予想通り、シェル企業の問題は期間を直しても残る。**
  これはユニバースゲート（§6）の仕事であって、期間合成の仕事ではない。

#### 実装で踏んだ2つ目のバグ — 期間の順序

修正の初回は **6,847 社ではなく 6 社**しか整合しなかった。
`ttm()` が `periods` を**新しい順**、`avg_bs()` が**古い順**で返していたため、
`aligned()` が **TTM の最古の四半期と AVG の期末**を比べていた。
構造的に12ヶ月ずれるので、ほぼ全社が弾かれる。

→ `Composed.periods` を**昇順に統一**し、`latest()` を経由するようにした。
**順序の取り違えを検出する回帰テストを追加した。**

> **2回続けて「実データで測ったら異常な数字が出た → 自分のコードのバグだった」。**
> Z12（訂正率 7.21% → 1.71%）と同じ形である。
> **測定結果が不自然なら、まず自分の実装を疑う**という規律が、

#### 問題2 — ユニバースを通さないと断面をシェル企業が支配する

**|ROA| > 1（総資産より損益が大きい）が 726 / 5,783 社（12.6%）。**

最悪: cik=1572386  NI=-1,581,000 / TA=**1** → ROA = -1,580,735
      cik=1265521  NI=  -416,500 / TA=**294**

**計算は正しい。実態が異常なだけである。** 総資産が数百ドルのシェル企業。

#### さらに追記 — 会計恒等式による導出でカバレッジを上げた

タグが無いだけで**定義上導出できる**ものがあった（DERA 8,714社での実測）。

| 導出 | 式 | 導出できる企業 | 性質 |
|---|---|---|---|
| GP | `REV − COGS` | 1,016社 | **恒等式**（厳密） |
| TL | `TA − EQ` | 766社 | ほぼ恒等式（非支配株主持分の扱いで微差） |
| PRETAX | `NI + TAX` | 317社 | **近似**（下記） |

**PRETAX = NI + TAX は恒等式ではない。**
正しくは `NI = PRETAX − TAX − 非支配株主持分 − 非継続事業` なので、
下2つがゼロのときだけ厳密に成り立つ。**使う前に誤差を実測した**

| | 割合 |
|---|---|
| 相対誤差の中央値 | **ちょうど 0** |
| \|相対誤差\| < 1% | **75%** |
| \|相対誤差\| < 5% | 83% |
| 実効税率への影響が \|差\| < 0.01 | **86%** |

→ **E29（実効税率の「変化」）でのみ使う。**
非支配株主持分や非継続事業は同じ企業で持続するので、
**持続的な偏りは差分を取れば相殺される。** 水準を測る用途には使わない。

→ **E29 の上限はデータの入手性ではなく、
ユニバースの過半が赤字であるという実態で決まっている。**
これ以上コードを足しても増えない。

## 8. 戦略への影響

```
  ┌─ 検証の土台 ────────────────────────────────┐
  │ OSAP（1926-2024, 24k銘柄, 生存者バイアスなし）  │  ← 手法の妥当性を確認する場所
  │  + Ken French                                │     CRSP品質。ただし自前再現はできない
  └───────────────┬─────────────────────────────┘
                  │ 同じ手法を自前で再現できるか検証
                  ▼
  ┌─ 自前パイプライン ──────────────────────────┐
  │ 米国: SEC DERA/EDGAR（2009-, PIT, 廃止企業込み）│  ← 実運用と同じコードパス
  │ 日本: J-Quants + EDINET（未検証）              │
  └───────────────┬─────────────────────────────┘
                  │ 手法を移植
                  ▼
  ┌─ 日本株 ────────────────────────────────────┐
  │ 個人の優位性は最大（無カバー62%、信用残、東証改革）│
  │ だがデータの土台は最も脆い（廃止銘柄マスタ未解決）  │
  └─────────────────────────────────────────────┘
```

**最も危険なのは「OSAP で良い結果が出たので実運用に移す」こと。**
OSAP は CRSP ベースで、自前パイプラインとは別物である。
**OSAP のシグナルを自前 EDGAR データで再現し、相関を測る工程を必ず挟む。**
そこで一致しなければ、OSAP での検証結果は自分のシステムには適用できない。
