# 263AT パラメータ実装仕様 v0.1 — 曖昧さの排除

> **目的** — [01_parameter_catalog.md](01_parameter_catalog.md) の 661 パラメータを、
> **実装者（人間でも Claude でも）が読んで一意に実装できる**状態にするための共通規約。
>
> カタログの各行の「定義 / 計算式」列は短い。そこに書ききれない前提
> （どの会計期間か、いつから使えるか、欠損をどうするか、会計基準の差をどう吸収するか）を
> **ここで一括して決める。** 個々のパラメータに書くと 661 箇所でずれる。
>
> **作成日** 2026-08-23

---

## 0. なぜこの文書があるか

投資システムのバグは、たいてい**計算の間違いではなく定義の曖昧さ**から入る。

- 「PER」と書いたとき、実績か予想か、TTM か本決算か
- 「3月期決算の数字」を4月1日から使ってしまう（実際の開示は5月）
- 日本基準の営業利益と IFRS の営業利益を同じ列に入れる（のれん償却の有無で別物）
- 欠損を中央値で埋めた結果、小型株が暗黙に大型株の中央値を持つ

これらはどれも**バックテストでは検出されず、成績を良く見せる方向に効く。**
そして §1.9 の方針（選択せず全部入れて縮める）を取る以上、
661 個すべての定義が曖昧なままだと、縮小しても意味のあるものが出てこない。

**定義の厳密化は、パラメータを減らさずに品質を上げる唯一の方法である。**

## 1. 時間の定義（最重要）

### 1.1 3つの時刻を必ず区別する

| フィールド | 意味 |
|---|---|
| `event_date` | 事象が起きた日（決算期末、取引日、インサイダーが売買した日） |
| `disclosure_date` | 公表された日時（決算発表、EDINET/EDGAR 掲載） |
| `available_at` | **自分が実際に使えるようになった時刻**（配信ラグ・取得バッチの実行時刻を含む） |

> **唯一の PIT ルール**: すべてのパラメータは `available_at <= t` のデータだけで計算する。
> `event_date` を使った時点でルックアヘッドである。

### 1.1.1 同じ期間の数字は何度も提出され、値が変わる（実測）

SEC EDGAR の `companyfacts` を実測したところ、同じ `(タグ, 期間)` が複数回提出されるのは
**例外ではなく常態**だった（AAPL の `NetIncomeLoss` は123期間中112期間、91%）。
しかも値が変わる期間があり、`NetIncomeLoss` の 2009年6月期は **1,229 と 1,828 百万ドル（48.7%差）**の2値を持つ。

```
# 正しい: 時点 t の投資家が見ていた値
value_as_of(tag, period, t) = { filed <= t を満たす行のうち filed が最大のもの }.val

# 誤り: 訂正後データを使ってしまう（バックテストが静かに良くなる）
value(tag, period)          = { 全行のうち filed が最大のもの }.val
```

`groupby([tag, end]).last()` と素直に書くと後者になる。**Z14 のテストで必ず検出する。**
詳細な実測値は [03_data_feasibility.md §2.1](03_data_feasibility.md) を参照。

### 1.2 主要データの開示ラグ

| データ | event_date | disclosure_date | 実務上のラグ |
|---|---|---|---|
| 決算短信（日本） | 決算期末 | 期末後 30〜45日 | **約1.5ヶ月** |
| 有価証券報告書（日本） | 決算期末 | 期末後 3ヶ月以内 | **約3ヶ月**。有報のみの項目（W02-W05、政策保有）はここまで待つ |
| 適時開示（TDnet） | 決定日 | 即日 | 分単位 |
| 大量保有報告書 | 義務発生日 | 5営業日以内 | **約1週間**。M11 が効くのはこのラグの間 |
| 信用取引残高 | 毎週火曜時点 | 翌週第2営業日 | **約1週間** |
| 空売り残高報告 | 発生日 | 翌々営業日 | 2営業日 |
| 10-K / 10-Q（米国） | 期末 | 大規模企業で 40〜60日 | 約1.5〜2ヶ月 |
| Form 4（米国） | 取引日 | **2営業日以内** | **最も速い。M02-M06 が米国で強い理由** |
| 13F（米国） | 四半期末 | **45日後** | **最も遅い。K22-K25 は単独では使えない** |
| アナリスト予想 | — | 随時 | ベンダーの配信タイミングに依存。要記録 |

**このラグの差がそのままシグナルの鮮度差（Z04）になる。**
Form 4 は2営業日、13F は45日。同じ「インサイダー情報」でも使い方がまったく違う。

### 1.3 参照する会計期間の規約

「今の財務」が何を指すかを**1つに固定する**。混在させない。

| 規約コード | 定義 | 使う場面 |
|---|---|---|
| `TTM` | 直近4四半期の合計（P/L・CF）。B/S は直近四半期末 | **既定値。すべてのフロー項目は TTM** |
| `FY` | 直近の本決算（通期） | 年次でしか開示されない項目 |
| `FQ` | 直近の四半期単体 | 加速度・季節調整（C06, C21） |
| `AVG` | 期首・期末平均（B/S 項目をフローと突き合わせる時） | ROA, ROE, 総資産回転率 |
| `GUIDE_CO` | 会社予想（日本は義務開示） | A02, C19, C20, N09, N31 |
| `GUIDE_CONS` | アナリストコンセンサス | N02, N10, N11, N12 |
| `POINT` | 時点値（株価、時価総額、需給） | 価格系すべて |

> **同じ概念でも規約が違えば別パラメータにする。**
> A01（実績益回り, TTM）と A02（予想益回り, GUIDE_CO）を1つにまとめてはいけない。
> 予想の出所（会社 / コンセンサス / 四季報 K32）も分けて持つ。

### 1.4 決算期変更・不規則決算

- 決算期変更があった期は月数が12でない → **月数で年率化してから TTM に組み込む**
- `Z06` でフラグを立て、変更後2年間はその銘柄の成長系パラメータの信頼度を下げる
- **変更を無視すると成長率が +50% などの異常値になり、ウィンザライズで静かに消される。**
  消えるので気づけない。だから**フラグで明示的に検出する**

### 1.5 タイムゾーンと約定の規約

- すべての `available_at` を **UTC** で保存し、市場別に取引日へ変換する
- 日本: JST 09:00–15:30（2024年11月から後場は 15:30 まで）
- 米国: ET 09:30–16:00（サマータイムの切り替えを必ず扱う）
- **日本の引け後に出た米国の材料は、日本株には翌営業日に反映される。** 日米を跨ぐシグナルはここを間違えやすい
- **約定の既定: シグナル発生日の翌取引日の始値。**
  当日終値での約定は「引けを見てから引けで買う」ことになりルックアヘッド（§8-1）
- VWAP 約定を仮定する場合は、その旨をバックテスト設定に明記し、J02 の参加率上限を守る

## 2. 会計項目の正規化定義

日本基準 / IFRS / US GAAP は名前も中身も違う。**中間表現を1つ定義し、全部そこへ写像する。**

| コード | 定義 | 注意 |
|---|---|---|
| `REV` | 売上高・営業収益 | 総額基準 / 純額基準の差に注意（商社・EC） |
| `COGS` | 売上原価 | 販管費との区分が企業により異なる |
| `GP` | `REV - COGS` | B06/B07 の基礎 |
| `SGA` | 販売費及び一般管理費 | |
| `OP` | 営業利益 | **日本基準はのれんを償却、IFRS は償却しない** |
| `EBIT` | `OP + 恒常的な持分法投資損益` | 持分法が恒常的かは V11 で判定 |
| `DA` | 減価償却費 + のれん償却費 + 無形資産償却費 | CF計算書から取る（P/L だと不完全） |
| `EBITDA` | `EBIT + DA` | **IFRS 企業と日本基準企業の EBITDA は比較可能だが、OP は比較不能** |
| `NI` | 親会社株主に帰属する当期純利益 | 非支配株主分を除く |
| `CFO` | 営業活動によるキャッシュフロー | |
| `CAPEX` | 有形固定資産の取得による支出 | 無形資産の取得は別に持つ |
| `FCF` | `CFO - CAPEX` | **定義に幅がある。263AT はこの1つに固定する** |
| `TA` | 総資産 | |
| `EQ` | `純資産 - 非支配株主持分 - 新株予約権` | いわゆる自己資本 |
| `IBD` | 短期借入金 + 1年内返済長期借入 + CP + 社債 + 長期借入金 + **リース負債** | リースを含めるか否かで D01 が変わる。**含める版を既定とし、含めない版も併存させる** |
| `CASH` | 現金及び現金同等物 + 短期有価証券 | |
| `ND` | `IBD - CASH` | 負値可（ネットキャッシュ企業） |
| `MCAP` | `株価 × SHARES` | |
| `EV` | `MCAP + ND + 非支配株主持分 - 持分法投資（簿価）` | 定義に幅がある。この1つに固定 |
| `IC` | `IBD + EQ - CASH` | 「超過現金のみ控除」版も別に持ち、どちらが効くか検証 |
| `TAXR` | `clip( 法人税等 / 税引前利益 , 0 , 0.6 )`。範囲外は業種中央値で代替 | E05 で異常をフラグ |
| `NOPAT` | `EBIT × (1 - TAXR)` | |
| `SHARES` | `期末発行済株式数 - 自己株式数`（**希薄化前**） | 潜在株式は F06 で別に持つ。分割・併合で必ず調整 |

### 2.1 会計基準の差で必ず問題になる3点

| 論点 | 内容 | 対処 |
|---|---|---|
| **のれん償却** | 日本基準は償却、IFRS/US GAAP は非償却（減損のみ） | OP・NI ベースの指標は基準間で比較不能。**EBITDA ベース（A06）を優先**。Z07 でフラグ |
| **リース（IFRS16 / ASC842）** | オンバランス化でレバレッジ指標が不連続に変化 | `IBD` にリースを含める版を既定にし、D19 を別に持つ |
| **非GAAP（米国）** | 企業ごとに定義が違い、SBC 除外などで利益が水増しされる | **263AT は GAAP のみを使う。** 非GAAP との差は E07 として持つ |

## 3. 価格・出来高の定義

| 規約 | 定義 |
|---|---|
| 調整価格 | 株式分割・併合・株式配当で遡及調整。**現金配当では調整しない** |
| トータルリターン | 配当込み系列 `TR` を**別系列**で保持。S16（税）を差し引く前後の両方を持つ |
| リターン | `r_t = ln(P_t^adj / P_{t-1}^adj)` |
| 出来高 | **調整後株数ベース。分割時に出来高も調整すること**（忘れると J01/J09 が飛ぶ） |
| 売買代金 | `終値 × 出来高`。VWAP が取れるなら `VWAP × 出来高` |
| 売買停止日 | リターンは **0 ではなく欠損**。0 を入れるとボラティリティが過小評価される |
| ストップ高 / 安 | 約定不能フラグを立て、シミュレータで翌営業日に持ち越す（J11/J18） |
| 上場廃止 | 最終価格と**廃止事由**を記録。**一律 -100% は誤り**（TOB による廃止はむしろプラス） |
| 通貨 | 現地通貨で保存。円換算は集計・比較の時のみ |

## 4. 断面正規化の定義

| 規約 | 定義 |
|---|---|
| 業種分類 | ~~既定は GICS セクター~~ **【2026-08-23 確定】GICS は日本株で無料入手できないので使わない。日本＝東証33業種、米国＝Fama-French 49業種。`rank_sector` は市場内で閉じ、日米を跨ぐ比較はサイズ分位（J19）で揃える。** 詳細は §4.1。「真の競合」は T21 で別に持ち、A25/Q09 の母集団として試す |
| ランク化 | `z = Phi_inv( (rank - 0.5) / N )`。同順位は平均順位 |
| 母集団 | 「全体」「GICSセクター内」「時価総額分位内」の3種を作り、どれが効くかは検証で決める |
| ウィンザライズ | ランク化するので原則不要。生値を使う場合のみ 1% / 99% でクリップし `Z09` にフラグ |
| **欠損** | **中央値補完はしない。** `z = 0`（中立）+ **欠損フラグを別特徴量として持つ**（Z01） |
| 最小母集団 | `N_t < 30` のグループではランク化しない（欠損扱い） |
| `∩` 型の変換 | 最適点 `x*` を「業種内中央値」または「理論値」で定義し、`-abs(x - x*)` に変換してからランク化。**`x*` の決め方をパラメータごとにレジストリへ記録する** |
| `U` カテゴリ | **該当業種内でのみランク化する。** 非該当業種は欠損（業種横断のランクは意味を持たない） |

> **欠損の扱いが最も事故を起こす。**
> 中央値で埋めると「データがない小型株」が「平均的な大型株」に化ける。
> `z = 0` + 欠損フラグなら、モデルが「欠損であること自体」を学習できる（Z03）。


## 4.1 業種分類の確定（SP-03 / SP-04 の解決、2026-08-23）

§4 の表では「**既定は GICS セクター（日米で揃うため）**」としていた。
**これは実装できない。** GICS は S&P/MSCI のライセンス製品で、
**日本株の全銘柄分を無料で得る手段が存在しない。**

`tools/build_priority.py` のボトルネック分析で、
**業種分類が未確定であることが最大のボトルネック**だと判明した
（159 パラメータが業種分類だけを理由に作れない。しかも解放される筆頭が
N04 = 再現 t 13.69 と L01 = 9.93 という最高価値の2本）。
**これはデータを買う話ではなく設計を決める話なので、ここで決める。**

### 決定

| 市場 | 主分類 | 粗い分類（フォールバック） | 入手 |
|---|---|---|---|
| **日本** | **東証33業種** | 東証17業種 | JPX が銘柄一覧で公開。**無料・全銘柄** |
| **米国** | **Fama-French 49業種**（SIC から機械変換） | Fama-French 12業種 | SEC filing の SIC コード + Ken French の対応表。**無料・全銘柄** |

**GICS は使わない。** 日本株で得られない以上、
「日米で揃う」という利点は実現しないので、揃わない前提で設計する。

### 日米統合ランクは業種で取らない

これが最も重要な帰結である。

東証33業種と Fama-French 49業種は**対応しない。**
無理に対応表を作れば、その対応表の恣意性がすべての業種内ランクに混入する。

> **`rank_sector` は市場内で閉じる。**
> 日本株は東証33業種内、米国株は FF49 業種内でランクする。
> **日米を跨ぐ比較が要るときは、業種ではなくサイズ分位（J19）で揃える。**

これは §5（通貨）で「絶対額は円換算してから日米統合ランクを作る」と決めたのと
同じ思想である — **揃えられるものだけを揃え、揃わないものは市場内に閉じる。**

`params/_defaults.yaml` の `normalization_by_category` で
`rank_sector` としているカテゴリ（A/B/C/D/E/V/W）は、
**実装上は「市場 × 業種」の二重グループでランクする**ことになる。

### 最小母集団を満たせないときのフォールバック

§4 で「`N_t < 30` のグループではランク化しない（欠損扱い）」と決めた。
東証33業種のうち小さいもの（鉱業・水産農林・ゴム製品など）は
プライム+スタンダードでも 30 社に届かないことがある。

```
rank_sector(i, t):
    g = 主分類（JP: 東証33業種 / US: FF49）
    if N(g, t) >= 30:  そのグループ内でランク
    else:              粗い分類（JP: 東証17業種 / US: FF12）に落とす
    if まだ 30 未満:    市場全体でランクし、Z09 にフラグを立てる
```

**粗い分類に落とすときは、その粗い分類の全銘柄と比べる。**
既に主分類でランク済みの銘柄も母集団に含める。
そうしないと「主分類で30に届かなかった銘柄どうし」という
意味のない集団で順位を付けることになる（`src/normalize.py` の実装で一度間違えた）。

#### 実測 — フォールバックは「念のため」ではなく常時発動する

2026-08-23 に JPX の銘柄一覧を実取得した（3,903 銘柄、ETF/REIT を除く普通株）。
**東証33業種のうち9業種が30社未満**だった。

| 業種 | 社数 | | 業種 | 社数 |
|---|---|---|---|---|
| 鉱業 | 5 | | 水産・農林業 | 12 |
| 空運業 | 7 | | 保険業 | 16 |
| 石油・石炭製品 | 9 | | ゴム製品 | 17 |
| 海運業 | 11 | | パルプ・紙 | 25 |
| | | | 電気・ガス業 | 29 |

**日米で必要な段数が違う**（2026-08-23、DERA 2024q3 の 10-K/10-Q 提出企業と
JPX 内国株式 3,713 銘柄で実測）:

| 市場 | 主分類で30社未満 | 粗い分類に落とした後 | 3段目（市場全体）が要るか |
|---|---|---|---|
| 米国 | **14 / 49**（FF49） | **0 / 12**（FF12） | **不要** |
| 日本 | **9 / 33**（東証33） | **2 / 17**（東証17） | **必要** |

日本で17業種でも足りないのは **エネルギー資源（14社）と 電力・ガス（29社）**。

→ **さらに重い含意: U-7（資源・海運）と U-1（金融のうち保険）は、
東証33業種の中で単独では断面ランクを作れない。**
**しかも「エネルギー資源」は17業種に落としても14社しかないので、
U-7 の日本株は業種内ランクが原理的に作れない** — 市場全体で比べるか、
米国の `Oil` / `Mines` / `Coal` と日米横断で比べるしかない。
§4.1 で「rank_sector は市場内で閉じる」と決めた方針の、
**唯一の例外候補**として記録しておく。
U カテゴリはもともと業種内でしかランクしない設計（`rank_industry`）なので、
**これらの業種の U パラメータは17業種に落とすか、
日米を跨いで比較するしかない。**
U カテゴリを検証したときには気づいていなかった制約である。

**落としたことをフラグで記録する。** 黙って市場全体でランクすると、
小業種の銘柄が「業種調整されている」と誤解したまま使われる。

### SP-04（U カテゴリの業種判定）— どの銘柄にどの業種KPIを適用するか

U カテゴリは8つの業種群に分かれている。
**東証33業種から機械的に写像する。**

| U の業種群 | 東証33業種 | 米国 FF49 |
|---|---|---|
| U-1 金融（U01-U08） | 銀行業 / 証券商品先物 / 保険業 / その他金融業 | Banks / Insur / Fin |
| U-2 不動産・REIT（U09-U14） | 不動産業 | RlEst |
| U-3 小売・外食（U15-U20） | 小売業 / 卸売業（一部） | Rtail / Meals |
| U-4 製造（U21-U26） | 電気機器 / 機械 / 精密機器 / 輸送用機器 / 金属製品 | Mach / ElcEq / Chips / Autos |
| U-5 IT・SaaS（U27-U33） | 情報・通信業 / サービス業（一部） | Softw / BusSv |
| U-6 医薬（U34-U38） | 医薬品 | Drugs / MedEq |
| U-7 資源・海運（U39-U42） | 鉱業 / 石油石炭製品 / 海運業 / 鉄鋼 / 非鉄金属 | Mines / Oil / Trans / Steel |
| U-8 建設・公益（U43-U45） | 建設業 / 電気・ガス業 / 陸運業 | Cnstr / Util |

**「（一部）」と書いた3つは機械的に決まらない。**
情報・通信業には NTT も無名の SaaS も入るし、
サービス業には人材派遣も外食も入る。
→ **T21（真の競合の特定）で LLM に判定させ、
その結果を `params/_industry_overrides.yaml` に固定して人が確認する。**
LLM の判定を毎回走らせると結果が揺れるので、**一度決めたら固定する。**

### 業種は時系列で持つ

§9 の落とし穴14「業種分類の遡及適用」の通り、
**現在の業種で過去を評価してはいけない。**
事業転換した企業（例: 繊維メーカーが電子部品に転換）を
現在の業種で過去まで遡って分類すると、**当時の同業と比較していないことになる。**

→ **東証33業種は銘柄一覧のスナップショットを月次で保存する。**
JPX は過去分を公開していないので、**今日から蓄積するしかない。**
それまでは現在の業種を使い、**Z07 相当のフラグで「業種は現在時点のもの」と記録する。**

> これは X カテゴリ（オルタナデータ）と同じ「過去に遡れない」制約が、
> **業種分類という基礎的な部分にも存在している**ということである。
> 気づいていなかった。

## 5. 通貨・為替

- 比率（PER、ROE、成長率）は通貨に依存しないのでそのまま日米比較可
- **絶対額（時価総額・売買代金・建玉）は必ず円換算してから日米統合ランクを作る**（J19）
- 為替は `available_at` 時点のスポット。ヒストリカルは日次終値
- 米国株の損益は**株価要因と為替要因に分解して記録する**（S18）

## 6. ユニバースの定義

```
UNIVERSE(t) = { i :
      上場している(t)                        # 上場廃止銘柄も「過去のその時点では」含む
  and 上場後経過月数 >= 6                     # IPO直後の値付け不安定期を除く（N24 は別に減点）
  and 平均売買代金(20d) >= 600万円            # J01: 60万円の建玉を参加率10%で3日以内に処分できる
  and 出来高ゼロ日数(60d) == 0                # J10
  and 円換算時価総額 >= 30億円                 # rho で可変（§1.6）
  and 整理銘柄・監理銘柄でない                 # N23
  and 継続企業の前提に関する注記がない          # D13
  and 直近の監査意見が無限定適正               # E22
}
```

> **必ず「その時点で」判定する。**
> 現在のユニバースで過去を検証すると生存者バイアス（§8-2）が入り、成績が劇的に良く見える。

## 9. 既知の落とし穴カタログ

実装中に踏みやすい順に並べた。**すべて自動テストで検出できるようにする。**
